# /pair-stress — 配对/OTA 压测执行卡

**一句话**：让“跑一晚上拿到可复核数字”变成流程而不是运气；判据先写、失败必恢复、原始日志必落盘。

## 何时用

- 要跑配对循环（串口 / 真实 APP / 混合复位）
- 要跑 OTA 正常或异常压测
- 要复现“配对不可用 / 偶发失败 / 一轮就卡住”

## 正本

- SOP：`develop_log/sop/配对压测SOP_20261109.md`（六机制、预检、退出条件、坑表）
- 计划：`plans/20261109_配对压测与基本功能外包APP.md`（A2/A3/A4 判据）
- 历史：`reports/overnight_test_analysis_20260509.md`（45,250 轮 99.39%）

## 工具

| 工具 | 用途 |
|---|---|
| `tools/app_battle/bench_ports.py` | 端口唯一源（108/74/95/54），`BENCH_<ROLE>` 覆盖；带在场探测 |
| `tools/app_battle/pair_bench.py` | 压测骨架：`preflight` / `sniff` / `send` / `run --dry-run` |
| `tools/app_battle/gui_metrics.py` | 真实 APP 点击→界面出现时延（分辨率 ~2.3s，只判秒级） |

## 开跑前 6 预检（任何一项不过 → 不许跑）

1. `py -3 -I tools/app_battle/bench_ports.py` 四口可开、字节>0
2. 三端 BUILD/md5 与预期一致
3. `pair_bench.py sniff` 抓现固件关键词（**严禁沿用旧固件关键词**）
4. 信标族对账（跟随者 `[BCNAD] cur=` 反查）
5. 10min 健康门：p0≥15、零秒≤20%
6. 地址/模式/固件快照存档

## 硬规则（违反=数据作废）

- 每轮四关键词终态，主机 15s / 从机 18s 超时
- 指令送达前置：两端都见回显才开跑，各重发 ≤20 次
- 失败必复位恢复；成功等 `Pairing Stopped` 再下一轮
- 判据预注册：成功率 ≥98%、不可恢复=0、负门执行率 100%
- 退出条件写死：同故障连续 3 轮停、设备不可恢复停、2 检查点无进展停
- 禁止跑一半改判据/关键词/端口

## 坑（高频）

- 端口三套口径 → 只用 `bench_ports.py`
- 同口重复打开 → 读写共用句柄
- 0xAA expect 错拍 = 假成功 → 验槽位+数据流，不看 toast
- post-pair BLE hold 60s → 轮隔 ≥70s
- 锚质量差 → 配对前过健康门
- **禁止对手机盲发 POWER/MENU**（会被锁在 PIN 界面，2026-11-09 事故）
- ~~单夜同一端复位 ≤2 次~~ **（11-09 撤销：AI 自造约束）**；复位不起就换带尾块镜像重烧

## 收口

原始日志 + 每轮 CSV + 汇总报告（样本量/成功率/失败分类/连续失败/置信区间）+ daily 三问 + 计划回填；失败另登已试路径。
