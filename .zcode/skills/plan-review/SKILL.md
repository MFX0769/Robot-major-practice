# plan-review — 实验/工作计划审查（2026-10-09 立 · 调研+本土教训合成）

> 触发：新实验计划落盘后、执行前、接手他人计划、或用户说"审一下计划"。
> 调研基线：Eppo/Columbia/Optimizely 实验计划与 QA 清单（问题/假设/归属/纳入标准/主次指标/干系人审查）
> + 本土三血案（2026-10-09）：A 臂零刺激跑 20min 全绿无意义 / 注入压测 remote.log 0 字节采集空转 /
> NO ESC 只认 0x61 不认空 ACK——指标语义与结论错配。

## 五步流程

1. **Steel-man 复述**：2-3 句复述计划要解的问题与判据（防稻草人）
2. **十项清单逐项审**（下方）——每项 pass/fail + 证据；fail 必须给修法
3. **Pre-mortem**：假设计划已跑完且结论作废，倒推最可能死因（Gary Klein 法）
4. **三档判决**：Sound with caveats / Needs rework / Investigate first
5. **修订回写**：修订建议直接回写计划文档对应节，不另开新文档

## 判决纪律

- 三档，不写"总体不错但"；Critical/Major 必须附文件:行号或数据证据
- fail 项不修完不上称"计划就绪"；修不完的转 Investigate first
- 审查结论与修订回写后，在该计划文档头部记一行"YYYY-MM-DD HH:MM plan-review 过/改"

## 与既有机制的关系

- 新实验立项前的 critic（AGENTS 质疑条款）= 对**方案**；本 skill 对**计划文档**——计划文档先过本 skill，再进执行
- 对赌预注册（stress-test 规则1）与本清单第 2 项同源，别重复写两处
