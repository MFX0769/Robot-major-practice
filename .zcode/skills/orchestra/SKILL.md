# /orchestra — 前台统筹 + 后台并行 操作卡

> 一句话：**主会话是运筹端不是执行端**；前台只做"派活、验收数字、写日志、对账"，抓串口/烧录/长测一律派后台；机械录制用后台终端脚本（零 token）。

## 0. 分工铁律（什么进哪里）

| 工作 | 去处 | 理由 |
|---|---|---|
| 决策、派活、验收数字、写日志、对账 | **前台主会话** | 保持全局视角，防代理偏题 |
| 抓串口、烧录、跑长测、大仓考古、社区调研 | **后台子代理**（run_in_background） | 省 token、可并行、失败不连坐主会话 |
| 机械录制/长跑采集（soak、周期采样） | **后台终端脚本**（python 写 CSV，`&` 挂起） | 不烧 token 不撞并发 |
| 只读侦查（枚举端口、读几秒特征行、grep 源码） | **前台**（允许） | 轻量，维持前台判断力 |

## 1. 子代理生命周期

1. **同一任务线必须复用**：`SendMessage(to=agent_xxx)` 续跑，保留它已侦察/已试错的上下文；禁止"换角度就新开从零摸"。
2. 新开代理仅三种正当理由：新任务线 / 老代理上下文污染且方向错 / 不可恢复。
3. **僵尸清理**：会话 agent 目录会累积墓碑（completed/stopped/failed 不占资源）；真正的僵尸=metadata 标 running 但无活进程——用 `Get-CimInstance` 核实后改状态，**注意 powershell 自匹配陷阱**（查询串里含目标 id 会匹配到自己）。
4. 并发上限听用户指令（默认不开满；闹钟轮内禁同口双代理）。

## 2. 防偏题三闸（用户 11-17 点名：没监督必偏题钻牛角尖、压缩后重做）

1. **正本指向闸**：长自主迭代前立"执行正本"文件（时间线+预注册判据+回退路径），闹钟/子代理每轮**先读正本**——上下文压缩后靠它恢复，不靠记忆。
2. **抽查核验闸**：子代理的每个关键结论，前台**抽查核源码/原始日志**再采信。当晚实战：代理三次误判（0x52000 是备份槽不是 app 区、切 BLE "挂死"实为抓包时机、0xAC 帧格式混淆）全靠前台核源码纠正。
3. **回退测试前置闸**：任何"继续往下做"之前先问一句——**这个问题之前做没做过？做过回退测试没有？**（新增：调研代理专门盘点此前相关尝试，防重复造轮子）。

## 3. 每轮监工循环（闹钟触发时照做）

1. 当场枚举端口 + 读特征行（只读；探不到记"本轮不可达"，禁判硬件坏）
2. `SendMessage` 问在跑代理进度（要数字：做了什么/卡哪/下个交付何时）
3. 推进正本当前阶段（能自主做的派代理；需授权的报用户）
4. 落盘：过程 append `temp/*.md`，结论 append weekly + 正本 §状态
5. 汇报 ≤8 行：端口 / 代理进度一句话 / 推进到哪 / 下轮关注点。连续 3 轮零新数字 → 写原因 append，**继续不停止**

## 4. 代理结论采信协议（前台必做）

- 采信前抽查：源码 `文件:行号`、原始日志行、二进制证据三选一；
- 代理之间互相矛盾的结论（"挂死"vs"成功"），**前台亲自做一次受控实测裁决**（当晚：`0xAB` 切 BLE 代理报挂死，前台 12s 抓到 363 行 done+SCAN，证伪）；
- 代理的"紧急风险"判断（如"app 区被擦会变砖"）**先核地址语义再恐慌**（当晚 0x52000 是备份槽，非 app 区）。

## 5. 与现有资产的关系

- 判据正本：`develop_log/sop/` 对应 SOP；执行正本：`develop_log/plans/` 当前计划（正本指向切换=改父计划头部，不用改闹钟）
- 汇报模式：长自主运行后用 `/exp-report` §2.7 任务对账模式
- 实验残留：`git stash push -m "存档说明"`（可回找），**工作区只留目标改动**（一码一包）
- 落盘三步：按用途选目录 → 写文件 → 当场在目录 README 登记

## 6. 11-17 深夜实战教训（用户点名加入）

### 6.1 "测不出问题"≠"没问题"
用户原话："当测不出问题也未必是真的测不出，因为当时的压测其实是没跑起来。"
**规则**：声称"全绿/没问题"之前，必须确认**压测真的跑起来了**（有 N/N 数字、有原始日志）。
"没报错"可能只是"没执行到那一步"。7-8 月考古发现：当时 OTA 全链确实通了（有 5/5 记录），
但配对压测 N/N 口径是 6 月的 ESC 线（85%→96%），8 月没有独立配对压测——**不能把"没跑"当"通过"**。

### 6.2 反编译源码是武器，不是摆设
用户原话："APP 那边不是你反编译已经基本上得到它的源码了吗？这个不能去核对一下吗？"
**规则**：拿到外包 APP 的 Dart 源码后，**必须用它来证明"是他们的问题"**——
不是只读一遍就放着，而是逐函数对照我们的固件行为，找出 APP 侧逻辑缺陷并写成可发的问题单。
今晚已做到：`scanResultLooksLikeHost()` 无名称兜底 / `trigger24GPair` 只发 1 字节 /
`unbindHostBestEffort` 是 onTap 人工触发。这些就是"用源码证明是他们的问题"。

### 6.3 回退测试必须"只提取旧包，不动当前代码"
用户原话："真的要保存好当前代码，当时的包提取出来，一定要只把当时的包提取出来，来去操作。"
**规则**：
- 回退测试 = **烧旧包**，不是 git checkout 旧代码重编（那会引入新的编译差异）
- 旧包从 `temp/ship_package_*/` 或 `output/ship/*/` 提取，**md5 核对后直接用**
- 当前工作区代码**不动**（stash 或保持原样），只换板上的固件
- 这样回退实验的变量只有一个：**板上固件版本**，排除编译环境差异

### 6.4 前台自身也会钻牛角尖（今晚 5 次翻车）
今晚前台在 OTA 线上连续 5 次"找到了→又错了"：
头陈旧→降级→IMU阻塞→改错树→擦除损坏→帧CRC bug。
**规则**：连续 2 次推翻自己的结论 → **停下来判 BLOCKED**，不再猜。
把确定事实列出来，缺什么 fixture 写清楚，等用户或换方向。
**不许第 3 次还说"找到了"。**

### 6.5 命令行优先于 GUI
用户原话："这个就跟我点击没关系了呀。"
**规则**：自研 APP（io.otaprobe）有 probe_cli.py 命令行控制面（adb broadcast），
**OTA/配对/扫描全程命令行可跑，不需要任何人点 GUI**。
GUI 只在"必须模拟真实用户操作"时才用（如验证外包 APP 的 UI 流程）。
**别把"UART 命令撞睡眠窗口"当成"固件挂死"**——多发几帧就行。


### 6.6 判"必须人"前先穷尽自主四能（2026-11-20 用户令）
用户原话："所有睡眠都是我们自己代码的逻辑，复位引脚也接了，从来不会有什么睡死了需要人来摇醒——不会出现这种情况。"
**事实**：遥控/踏频深睡=自研代码逻辑（非 SoC 神秘态），唤醒源=UART_RX **IO 外部中断（我们自己开的）**——电脑 TX 发任意字节即醒；所有台架设备接了复位引脚（124=pw-rst 专用时序，非裸 RTS 翻转），复位不行还能复位+重烧/全擦全烧；手机可 adb input 解锁（PIN 单次提交防锁死）；白名单口被占→认明 PID 直接杀（含用户 GUI）。
**规则**：报"必须人来操作"之前，必须逐项核过四能清单（UART唤醒/复位通道/adb解锁/杀占用）并登记"已试 N 项"。历史教训："断电才活"（实为 pw-rst 方法用错）、"输不了 PIN"（实为 input text 没试）多为方法没用尽，不是真边界。真正必须人的只剩两类：硬件物理故障（线断/板烧，修硬件非操作）+授权决策（行为改动/对外发包，规则上故意留人）。
