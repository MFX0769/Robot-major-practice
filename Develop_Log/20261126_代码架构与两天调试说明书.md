## 0. 先读这一页

### 0.1 这套代码是什么

这是一台 STM32H723 四轮麦轮车上的比赛调试固件。
它同时负责：

1. 四个 M2006/C610 轮组电机。
2. 一个 GM6020 机械臂底座 yaw 电机。
3. 两个星呗 SP 系列总线舵机（肩、肘）。
4. 一个 PWM 夹爪。
5. 八路模拟量巡线模块。
6. 一个前向 TF-mini Plus 激光测距模块。
7. DBUS 遥控器接收。
8. 七字节水果视觉协议。
9. 单按钮拖动示教、死程序采摘、平面两连杆逆解。
10. USART10 与板载 USB 两路调试控制台。

它不是产品级框架，而是为 2026-11-26～27 两天现场调试优化的工程。
因此保留了旧任务、旧协议和旧注释；阅读时必须以“实际被 main/freertos/Keil 工程调用的路径”为准。

### 0.2 下午调试的总顺序

严格按下面顺序，不要一上电就开巡线：

1. 只接调试口，烧录，确认串口有启动日志。
2. `flash test`，确认片内 Flash 可写。
3. 接 24V，轮子离地，确认 CAN1 四个电机反馈。
4. 单轮开环点动，确认 ID、方向和电流槽位。
5. 确认 CAN2 的 6020 反馈与控制帧。
6. 确认肩/肘/夹爪通信和上电姿态。
7. 接 DBUS，看 `rc`、`uart`、`diag` 的帧计数和间隔。
8. 遥控直驱，确认四个拨杆和两个摇杆的语义。
9. 巡线，先直线、再弯道、再丢线。
10. 单路激光避障，先强行走流程，再接实物。
11. 机械臂 yaw 探测和位置环。
12. 拖动示教录 5 个采摘路点。
13. 视觉四点标定与 `ik learn here` 固定深度标定。
14. 全流程联调，任何一步不过都退回上一步。

### 0.3 最重要的六条命令

```text
diag
can stat
rc
chassis status
avoid status
yaw status
```

`diag` 是总入口。
它显示模式门控、最后拒绝原因、舵机/yaw 在线、视觉和巡线年龄、阈值、日志丢弃。
如果机械臂不动，先发 `diag`，不要连续试很多运动命令。

### 0.4 最重要的事实

- CAN1：四个底盘电机，控制帧 0x200，反馈 0x201～0x204。
- CAN2：6020，控制帧 0x1FF，反馈 0x208。
- 6020 控制的是电压，不是电流。
- 右摇杆控制车体平移；左摇杆横控制旋转。
- 巡线需要“底盘拨杆在下”且“全局模式不是保护”。
- `mode manual` 只放开机械臂，同时锁住底盘。
- `chassis line` 必须 5 秒内连发两次。
- 关节默认限位很窄，大幅动作前必须 `joint limit`。
- yaw 必须先 `yaw probe` 或手动 `yaw dir`。
- 视觉没有 Z；固定深度默认 250 mm，必须现场标定。
- TF-mini 接 UART9_RX=PD14，即扩展排针 11。
- 日志队列满会丢日志，但不会阻塞控制任务；丢弃计数现在可见。

### 1.4 镜像与轨迹 Flash 的关系

固件镜像从 0x08000000 开始。
当前 Load Region 大小 0x0002A5AC。
因此镜像末地址为 0x0802A5AC。

轨迹槽：

- A：0x080C0000，扇区 6。
- B：0x080E0000，扇区 7。

两者都远在镜像之后。
新增代码时仍要检查 map，不能让镜像越过 0x080C0000。

## 2. 上电初始化与任务图

### 2.1 main 的初始化顺序

`Core/Src/main.c` 的关键顺序：

1. `HAL_Init()`。
2. 时钟和系统初始化。
3. GPIO、DMA、ADC、TIM、SPI、UART、FDCAN、OCTOSPI 等外设。
4. `MX_UART5_Init()`：DBUS。
5. `MX_UART7_Init()`：巡线。
6. `MX_USART10_UART_Init()`：调试串口。
7. `MX_FDCAN1_Init()`：底盘 CAN。
8. `MX_FDCAN2_Init()`：6020 CAN。
9. `USER_UART_Init()`：业务串口补充配置。
10. `comm_can_init()`：注册电机、过滤表、启动 CAN。
11. `dbg_init()`：日志队列和启动横幅。
12. `MX_FREERTOS_Init()`：建队列、建任务。
13. `osKernelStart()`：启动调度。

### 2.2 CAN 初始化为什么关键

`comm_can_init()` 做四件事：

1. 写 CAN1 过滤表。
2. 写 CAN2 过滤表。
3. 初始化 6020 对象。
4. 初始化四个 2006 对象。
5. 通过 `bsp_can_init()` 启动两个 FDCAN。

CAN1 过滤范围：

- 0x017～0x019：IMU。
- 0x201～0x204：四个底盘电机。
- 0x208：备用 6020。
- 0x205～0x207：诊断空槽。

CAN2 过滤：

- 0x208：6020 反馈。

如果 `chassis status` 四个 `on=0`，先怀疑过滤、供电、接线和终端电阻。
不要先改 PID。

## 3. 模式与门控：为什么设备不动

### 3.1 两层模式不是一回事

全局模式 `ctrl_mode`：

- `PROTECT_MODE=0`：保护。
- `REMOTER_MODE=1`：遥控。
- `KEYBOARD_MODE=2`：保留。
- `VISION_MODE=3`：视觉。
- `ARM_TEACH_MODE=4`：机械臂/示教。

底盘专用模式 `chassis_mode`：

- `CHASSIS_STOP`：停。
- `CHASSIS_REMOTER`：遥控直驱。
- `CHASSIS_LINE_TRACK`：巡线。

底盘拨杆 `sw2` 决定底盘模式。
全局拨杆 `sw1` 决定全局模式。

### 3.2 DBUS 解锁

`unlock_init()` 的条件：

```text
rc.sw1 == 3（中）
rc.sw2 == 1（上）
rc.ch4 <= -600
rc.ch3 >= 600
rc.ch1 <= -600
rc.ch2 <= -600
```

翻译：

- 左拨杆中。
- 右拨杆上。
- 左摇杆右下。
- 右摇杆左下。

满足后 `lock_flag=1`。
没解锁时全局模式保持保护。

### 3.3 全局拨杆模式

- `sw1=1`：REMOTER；但 `ch4<=-600` 时进入 VISION。
- `sw1=3`：PROTECT。
- `sw1=2`：ARM_TEACH。
- 其它：PROTECT。

现场陷阱：

左拨杆上并且左摇杆竖着推到顶，会进 VISION。
VISION 不在机械臂允许集合，`joint` 和 `yaw` 会被拒。
如果你只是想遥控底盘，把左摇杆竖回中。

### 3.4 底盘拨杆模式

- `sw2=2`：REMOTER。
- `sw2=0`：LINE_TRACK。
- 其它：STOP。

巡线真正启动条件：

```text
sw2 == 0
ctrl_mode != PROTECT_MODE
arm_busy == 0
```

`ctrl_mode` 是 REMOTER 或 ARM_TEACH 都能让底盘输出。
但 `arm_busy=1` 会把给定归零。

### 3.5 `arm_busy`

`arm_busy=1` 的条件：

```text
arm_ctrl.manual == 1
或 teach.state == READY
或 teach.state == RECORD
或 teach.state == PLAYBACK
```

`arm_busy=0`：

- IDLE。
- SAVED。
- ABORT。
- 非 manual。

作用：

- 底盘给定归零。
- 轮组闭环刹车，不是直接把电流永远置零。

### 3.6 机械臂运动允许条件

`arm_motion_allowed()`：

```text
arm_ctrl.chassis_run == 0
且 ctrl_mode == REMOTER_MODE 或 ARM_TEACH_MODE
```

所以：

- 保护模式：不允许。
- 视觉模式：不允许。
- 巡线运行：不允许。
- 遥控模式：允许。
- 示教模式：允许，但还要过示教状态门控。

### 3.7 `mode manual`

作用：

1. 拒绝在 READY/RECORD/PLAYBACK 使用。
2. `manual=1`。
3. `chassis_run=0`。
4. `mode_user_set(ARM_TEACH_MODE)`。
5. `arm_busy=1`。

目的：

只放开机械臂命令，底盘保持锁零。

### 3.8 `chassis line`

控制台两步确认：

第一条：

- 记录 `s_line_arm_tick`。
- 不启动。
- 打印 ARMED。

第二条：

- 距第一条不超过 5000 ms。
- 调 `arm_chassis_release()`。
- `manual=0`。
- `chassis_run=1`。
- `mode_user_set(REMOTER_MODE)`。
- 打印 RUNNING。

拒绝条件：

- 示教 READY/RECORD/PLAYBACK。
- 舵机配置模式。

### 3.9 关节点动拒绝码

`arm_joint_jog()` 返回：

- `-1`：参数或 joint 非法。
- `-2`：底盘运行或模式不允许。
- `-3`：回放中。
- `-4`：肩肘处于释力示教。
- `-5`：舵机配置模式。

夹爪在 READY/RECORD 仍允许点动。
肩肘不允许。

### 3.10 yaw 命令拒绝码

`yaw_gate()`：

- `-1`：舵机配置模式。
- `-2`：READY/RECORD 释力。
- `-3`：PLAYBACK。
- `-4`：方向未标定。
- `-5`：故障锁存。
- `-6`：底盘运行。
- `-7`：模式不允许。

`yaw probe` 的 `need_dir=0`，所以它能在方向未标定时运行。
但其它 yaw 命令不行。

### 3.11 回放拒绝条件

`teach_play_start()`：

- 正在 PLAYBACK：直接返回。
- 点数少于 2：拒绝。
- `saved_valid=0`：拒绝。
- 舵机配置模式：拒绝。
- 肩或肘离线：拒绝。

### 3.12 Flash 保存拒绝条件

`arm_flash_commit()`：

- `chassis_run=1`：返回 -9。
- 先让 `arm_busy=1`。
- yaw 立即零输出。
- 延时 40 ms 让零帧发出。
- 擦写 Flash。
- 恢复 `arm_busy`。

原因：H7 擦写时 CPU 取指停顿，期间发不出 CAN。

### 3.13 最后拒绝原因

所有主要拒绝路径现在调用：

```c
arm_diag_note_reject(code, why);
```

保存：

- `reject_count`。
- `reject_code`。
- `reject_why[40]`。

发 `diag` 可读最后一次。
例如：

```text
last_reject=-4 'yaw dir uncalibrated'
```

这比翻历史日志可靠。

## 4. CAN1/CAN2 与电机对象

### 4.1 电机下标、ID 和帧槽位

| `chassis_2006` 下标 | 电机位置 | CAN ID | 0x200 数据槽 |
|---|---|---|---|
| 0 | 左前 | 0x204 | 字节 6～7 |
| 1 | 左后 | 0x202 | 字节 2～3 |
| 2 | 右前 | 0x203 | 字节 4～5 |
| 3 | 右后 | 0x201 | 字节 0～1 |

控制台：

```text
chassis motor 0 800
```

就是左前电机，开环 +800，持续 1500 ms。

### 4.2 右侧电机方向

`target_rpm`：

```text
[0] = motor[0]
[1] = motor[2]
[2] = -motor[1]
[3] = -motor[3]
```

原因：右侧两个电机安装方向相反。

不要只改 `chassis map` 来修单轮方向。
单轮方向是电机安装和 ID 映射问题，应通过换 ID/换线/换下标确认。

### 4.3 轮组速度环

每个电机一个 PID：

- Kp=5。
- Ki=0。
- Kd=1。
- MaxOutput=8000。
- IntegralLimit=1600。

反馈：`chassis_2006[i].speed_rpm`。
目标：麦轮解算后的 RPM。

输出：`tx_current`。

### 4.4 保护与假给定

原来保护模式只把输出置零，PID 仍记得 1200 目标。
离开保护时会产生一拍微分冲量。

现在：

```text
arm_busy 或 STOP 或 PROTECT
=> vx_ref=vy_ref=wz_ref=0
=> 目标 RPM=0
=> PID 刹车
```

现场表现：

轮子不会瞬间物理停止，但给定立即为零并闭环刹住。

### 4.5 CAN 发送路径

```text
chassis_task
  -> dji_send_current(四个电机)
  -> Prot_CAN1_Send_Frame
  -> CAN1_Tx_queue
  -> Task_CAN1Transmit
  -> bsp_can_std_transmit
  -> HAL_FDCAN_AddMessageToTxFifoQ
```

6020：

```text
arm_task
  -> dji_send_current(&arm_yaw_motor)
  -> Prot_CAN2_Send_Frame
  -> CAN2_Tx_queue
  -> Task_CAN2Transmit
  -> 0x1FF
```

### 4.6 未注册电机保护

`dji_send_current()` 现在跳过：

```text
can_id < 0x201 或 can_id > 0x208
```

否则 `can_id=0` 会算出负槽位，写到帧外。

### 4.7 编码器累计

`dji_motor_get_single_data()`：

- 第一帧锁 `offset_ecd`。
- 第一帧不参与跨圈。
- 之后 ECD 跳变 >=4096：圈数减。
- ECD 跳变 <=-4096：圈数加。
- `total_ecd = round_cnt*8192 + ecd - offset_ecd`。

本轮修复：

旧代码前 50 帧反复锁原点并清圈数。
6020 上电后若很快跨 8191→0，第一圈会丢。
现在只第一帧锁原点。

### 4.8 编码器过零验证

测试覆盖：

- 8191→0：圈数 +1，`total_ecd=1`。
- 0→8191：圈数回 0，`total_ecd=0`。
- 8191→4000：大跳变换一次圈，`total_ecd=4001`。

现场验证：

1. `yaw monitor`。
2. 手动把 yaw 从 ECD 8000 附近推到 0 附近。
3. 看 `round` 是否连续变化。
4. 看 `total` 是否单调增加/减少。
5. 不要把 `total_ecd` 直接当 0～8191 限位坐标。

### 4.9 CAN 健康行

每秒：

```text
[CAN] c1 tx= rx= tec= rec= bo= off= fix= | c2 ...
```

判读：

- `tx`：交给外设的发送帧数。
- `rx`：收到帧数。
- `tec`：发送错误计数。
- `rec`：接收错误计数。
- `bo`：当前 bus-off。
- `off`：累计 bus-off 次数。
- `fix`：自动恢复次数。

关键：

当前 FDCAN 配置 `AutoRetransmission=DISABLE`。
所以没人应答时 `tx` 仍会增长。
不要用“tx 不涨”判断总线无人。

### 4.10 bus-off 恢复

使能 `FDCAN_IT_BUS_OFF`。
中断里：

```text
HAL_FDCAN_Stop
HAL_FDCAN_Start
```

过滤表和通知保留。

手动：

```text
can recover 1
can recover 2
```

### 4.11 CAN1 不通的检查顺序

1. 24V 是否到电调。
2. `can stat` 的 `rx` 是否为零。
3. CANH/CANL 是否接反。
4. 终端电阻是否存在。
5. 电调 ID 是否为 1～4。
6. 是否接到 CAN2。
7. 用 USB-CAN 监听 0x200 和 0x201～0x204。
8. 确认过滤表没有在上电后被覆盖。

### 4.12 CAN2 不通的检查顺序

1. `yaw status` 的 `on`。
2. `can stat` 的 c2 `rx`。
3. 6020 灯：橙闪可能 ID 重复。
4. 6020 红常亮可能没收到控制帧。
5. 控制帧是否 0x1FF。
6. ID4 是否在第 6～7 字节。
7. 是否误用 0x1FE 电流帧。

## 5. DBUS 遥控器

### 5.1 硬件参数

- UART5。
- PD2。
- 100000 bps。
- 8 数据位。
- Even parity。
- 1 停止位。
- 每帧 18 字节。
- 标称约 14 ms/帧，约 71.4 Hz。

### 5.2 收帧方式

`dbus_rx_isr()`：

1. 读 ISR。
2. 清 ORE/FE/NE。
3. 逐字节读 RDR。
4. IDLE 时切帧。
5. 长度必须恰好 18。
6. 入 8 深队列。

不能按帧头内容切帧。
第一字节是摇杆通道数据，会变化。

### 5.3 解析链路

```text
prot_dbus.c
  -> prot_dr16.c rc_callback_handler
  -> rc.ch1..ch5, sw1, sw2
  -> prot_sbus.c sbus_callback_handler
  -> wbus_rc.data
```

拨杆映射：

- DBUS 1 上 → wbus 2。
- DBUS 2 下 → wbus 0。
- DBUS 3 中 → wbus 1。

### 5.4 当前通道语义

按 DR16 标准解码：

- ch1：右摇杆横，左负。
- ch2：右摇杆竖，上正。
- ch3：左摇杆横，左负。
- ch4：左摇杆竖，上正。
- sw1：左拨杆。
- sw2：右拨杆。

底盘映射：

```text
vx = ch2 * 3.0 * map_vx
vy = ch1 * 3.0 * map_vy
wz = ch3 * 15.0 * map_wz
```

因此：

- 右摇杆上下：前后。
- 右摇杆左右：平移。
- 左摇杆左右：旋转。
- 左摇杆上下：巡线中触发表演。

### 5.5 解锁组合在新映射下是否一致

`unlock_init()` 要：

- ch4 左下？代码是 `ch4<=-600`，即左摇杆下。
- ch3>=600，即左摇杆右。
- ch1<=-600，即右摇杆左。
- ch2<=-600，即右摇杆下。

合起来是两摇杆向内下方。
和 6 月实测内八手势相同。

### 5.6 `rc` 命令

```text
rc
```

输出：

```text
ch1 ch2 ch3 ch4 sw1 sw2 sw3 lock dbus rx
```

现场调试：

1. 中位记一组。
2. 每个摇杆推到四方向各记一组。
3. 两个拨杆各切三档。
4. 确认符号和档位。
5. 再调 `chassis map`。

### 5.7 DBUS 统计

`diag` 和 `uart` 使用：

- `frames`：有效 18 字节帧。
- `bad`：坏长度或出错帧。
- `qdrop`：接收队列满。
- `interval`：最近帧间隔。
- `max`：最大帧间隔。

正常：

- `bad` 不增长。
- `qdrop` 不增长。
- `interval` 多数接近 14 ms。
- `max` 不应频繁出现数百 ms。

### 5.8 DBUS 队列为什么够用

队列 8 帧。
模式任务 5 ms 取一次。
标称帧间隔 14 ms。
正常每 14 ms 最多积一帧，5 ms 内取走。
只有任务被长阻塞或射频异常才会积到 8 帧。

### 5.9 DBUS 不通

1. `uart` 看 dbus bytes/frames。
2. `rc` 看数值是否变化。
3. 接收机是否供电。
4. PD2 是否接对。
5. 是否 100000 8E1。
6. 是否误当 115200 8N1。
7. 检查 `bad` 是否增长。

## 6. 调试控制台与串口负载

### 6.1 两路输入

- USART10：PE2 RX、PE3 TX，115200。
- 板载 USB CDC：同一解析器。

任何串口终端都可以。
命令必须以回车或换行结束。

### 6.2 行缓冲

- 最大 48 字节。
- 超过缓冲：丢弃当前行。
- CR/LF：提交一行。
- 空行：忽略。
- 命令队列：8 条。
- `arm_task` 每周期执行一条。

### 6.3 控制台统计

`diag` 显示：

- bytes：两路合计字节。
- lines：完整行数。
- enq：成功入队。
- qdrop：队列满丢弃。

如果命令发了没反应：

1. 看 bytes 是否涨。
2. 看 lines 是否涨。
3. 看 enq/qdrop。
4. 看是否超过 48 字节。
5. 看是否忘了换行。

### 6.4 日志双出口

每个 `dbg_print`：

1. 格式化到调用者栈。
2. 入 USART10 日志队列。
3. 同时尝试入 USB 日志队列。

两条出口独立。
USB 不通不应影响 UART10。
UART10 堵住不应阻塞控制任务。

### 6.5 USART10 日志队列

- 单条最大 192 B。
- 队列 8 条。
- 满则丢。
- `dbg_task` 低优先级发送。
- 单条 HAL 发送超时 100 ms。

统计：

- enq。
- drop。
- trunc。
- uart_tx。
- timeout。

### 6.6 USB 日志队列

- 单条最大 120 B。
- 队列 16 条。
- 双缓冲异步发送。
- 端点忙最多等 20 ms。
- 仍忙则丢。

统计：

- enq。
- qdrop。
- tx。
- busy_drop。

### 6.7 串口会不会爆

115200 8N1 的有效吞吐约：

```text
115200 / 10 = 11520 B/s
```

建议日志平均占用不超过 30%：

```text
约 3456 B/s
```

当前周期日志：

- CAN 健康行约 1 Hz。
- SYS 健康行约 1 Hz。
- yaw 运动时 20 Hz。
- 状态变化短日志。
- 用户命令回复。

正常远低于带宽。
真正风险是：

- 高频循环里打印。
- 每条日志都被双出口复制。
- USB 未枚举但仍持续入队。
- 多个任务同时打印。

### 6.8 日志过载判读

发两次 `diag`，间隔几秒：

- `drop` 增长：USART10 日志队列满。
- `trunc` 增长：单条超过 192 B。
- `timeout` 增长：UART10 发送超时。
- `USB qdrop` 增长：USB 日志队列满。
- `USB busy_drop` 增长：端点忙或 USB 未就绪。

处理：

1. 关 `yaw monitor`。
2. 不在循环里加高频打印。
3. 把多条信息合成一条快照。
4. 用 `diag` 替代连续查询。
5. 如果仍丢，降低日志周期，不能阻塞控制。

### 6.9 `diag` 内容

`diag` 一次打印：

1. 模式和互锁输入。
2. 最后拒绝原因。
3. 舵机和 yaw。
4. Flash 和 IK 参数。
5. 视觉年龄与新鲜度。
6. 巡线帧数和年龄。
7. DBUS 帧统计。
8. 控制台输入统计。
9. 日志和 USB 输出统计。

### 6.10 不要用 OpenOCD 作为第一诊断手段

原因：

- SWD 连接可能不稳定。
- halt 会影响实时任务。
- 变量优化后可能看不到。
- 现场重新配脚本耗时。

优先：

1. 串口日志。
2. `diag`。
3. 状态命令。
4. USB-CAN。
5. 最后才用 OpenOCD。

## 7. 底盘麦轮解算与遥控驾驶

### 7.1 麦轮坐标

定义：

- `vx`：车体前方。
- `vy`：车体右侧。
- `wz`：绕 yaw。

电机目标：

```text
motor0 = vx + vy + wz
motor1 = vx - vy - wz
motor2 = vx - vy + wz
motor3 = vx + vy - wz
```

随后右侧两个目标取反。

### 7.2 里程计逆解

避障使用：

```text
vx_body = (FL + BL - FR - BR) / 4
vy_body = (FL - BL + FR - BR) / 4
```

这里 FL/BL/FR/BR 是车体方向下的轮速。

### 7.3 `chassis map`

三个符号：

- vx。
- vy。
- wz。

值只能是 +1 或 -1。

命令：

```text
chassis map
chassis map vx -1
chassis map vy 1
chassis map wz -1
pick save
```

掉电保存位置：

- reserved[0]。
- reserved[1]。
- reserved[2]。

### 7.4 单轮点动

```text
chassis motor 0 800
```

参数：

- 下标 0～3。
- 电流非零。
- 自动限幅 ±3000。
- 1500 ms 后自动归零。
- 不受全局保护门控。

这是调试电机最快的方法。
现场车轮必须离地。

### 7.5 PID 在线调参

查看：

```text
chassis pid
```

设置：

```text
chassis pid 0 5 0 1
chassis pid line -12 0 0
```

范围：

- 轮组 PID：0～500，Ki/Kd 不可为负。
- 巡线 PID：Kp 允许 -500～500，Ki/Kd 不可为负。
- Kp 为负是当前误差约定的正常方向；默认 -12。

### 7.6 遥控驾驶验收

1. 解锁。
2. 左拨杆上，右拨杆上。
3. `rc` 看 sw1/sw2。
4. 车轮离地，右摇杆上下。
5. 确认四轮方向。
6. 右摇杆左右，确认平移。
7. 左摇杆左右，确认旋转。
8. 右拨杆中，确认立即目标归零。
9. 左拨杆中，确认保护。
10. 拔接收机，确认最终保护。

## 8. 八路巡线

### 8.1 硬件与协议

- UART7。
- 115200 8N1。
- 模拟量帧 `$A...#`。
- 数字量帧 `$D...#`。
- 每 2 秒补发读取命令。

### 8.2 帧时间戳

`ir_last_rx_tick` 是最近一次有效帧的 ms 时间戳。
`ir_last_isr` 是寄存器快照，不是时间。

`diag` 的 `line_age` 使用前者。

### 8.3 位置计算

八路模拟量加权质心。

结果范围：

```text
position ∈ [-100, +100]
```

状态：

- `LINE_STATE_OK=1`。
- `LINE_STATE_ALLON=2`。
- `LINE_STATE_LOST=0`。

### 8.4 巡线控制

正常：

```text
vx = 1200 - |position| * 5
最低 400
wz = line_pid(position, 0)
```

默认 line PID：

- Kp=-12。
- Ki=0。
- Kd=0。
- MaxOutput=150000。

`pid_calc(get, set)` 的误差是 `set-get= -position`。
Kp=-12，因此：

```text
wz = 12 * position
```

position=+100 时 wz=+1200。

### 8.5 为什么默认从 -50 改成 -12

旧值：

```text
wz = 50 * position
```

满偏差时 5000，约等于 4.2 倍基速。
容易蛇形、甩尾、丢线。

新值满偏差约等于基速。
仍必须现场整定。

### 8.6 丢线

- 保持最后 position。
- 700 ms 内按记忆方向转。
- `vx=350`。
- `wz=±900`。
- 700 ms 后给定归零。

方向：

```text
dir = (line_pid.p < 0) ? +1 : -1
wz = dir * sign(last_position) * 900
```

这样丢线转向与纠偏同侧。

### 8.7 上电两秒缓冲

`track_time` 从底盘任务启动开始累加。
前 1000 个 2 ms 周期，即约 2 秒：

- `vx=1200`。
- 不看线状态。
- 仍会受保护和 arm_busy 门控。

只有上电后立刻启动巡线才有这个缓冲。
停车后再启动没有。

### 8.7a 巡线判定阈值（容易误触发的数值）

`Protocol/prot_8irtraking.c` 的三个阈值：

- `LINE_THR_RATIO=0.5`：黑白阈值放在当前帧动态范围中间。
- `LINE_MIN_CONTRAST=150`：八路最大值减最小值低于 150，直接判丢线。
- `LINE_MIN_SUM=0.5`：八路黑度权重总和低于 0.5，直接判丢线。

黑度计算：

```text
blackness_i = clamp((threshold - analog_i) / (threshold - vmin), 0, 1)
```

这三个阈值是“当前帧相对量”，不是固定 ADC 值。
所以换模块、改高度、改黑白颜色后，阈值行为可能完全不同。

现场判断：

- `contrast` 长期低于 150：模块没数据、供电不足、安装太高或反光。
- `wsum` 长期低于 0.5：没有有效黑线，不是 PID 问题。
- 正常直道仍频繁 LOST：先打印八路值，再调阈值。
- 不要为了“跟线”直接把 150 改成 0，否则噪声会被当成线。

当前 `diag` 显示帧数和帧年龄，但还没有显示 `contrast/wsum/position` 的完整快照。
现场如果巡线状态不对，应优先补这三项打印，不要先改 Kp。

### 8.8 巡线调试顺序

1. `uart` 确认 U7 有帧。
2. `diag` 看 line_rx 和 line_age。
3. 车放线上。
4. `chassis line` 两条。
5. 先直线 2 米。
6. 摆头：减小 Kp 绝对值。
7. 拖尾：增大 Kp 绝对值。
8. 弯道甩尾：增大减速系数。
9. 丢线：看方向是否合理。
10. 终点全黑：直行冲过。

### 8.9 当前缺口

- 没有在控制台打印八路模拟量。
- 没有边缘预判三段式。
- 没有反向交替扫搜。
- 丢线失败只能停车。

这些是第二天才允许加的，不要第一天改乱主线。

## 9. 单路激光避障

### 9.1 硬件

- TF-mini Plus。
- UART9_RX=PD14。
- 排针 11。
- 115200 8N1。
- 9 字节帧。
- 默认距离单位 cm。
- 5V/GND。

### 9.2 帧格式

```text
59 59 distL distH strL strH tempL tempH sum
```

校验：

```text
sum = 前 8 字节累加和低 8 位
```

### 9.3 有效帧

必须满足：

- 最近 100 ms 内收到。
- strength >= 20。
- distance != 0。
- distance != 0xFFFF。
- 换算毫米后不超过 12000 mm。

### 9.4 重同步

CRC 失败时滑窗查找连续 `59 59`。
只保留必要前缀。
不会把 9 字节窗口全部留下导致下一次越界。

### 9.5 状态机

```text
IDLE
 -> STOP
 -> STRAFE_OUT
 -> AHEAD
 -> STRAFE_BACK
 -> IDLE
或 STRAFE_BACK
 -> RELINE
 -> IDLE / ABORT
```

### 9.6 默认参数

- 防抖：3 个新帧。
- 停止：300 ms。
- 横移：300 mm。
- 前进：450 mm。
- 回线额外搜索：150 mm。
- 每段超时：8000 ms。
- 完成后冷却：1500 ms。
- 触发距离：300 mm。
- 横移速度目标：600 RPM。
- 前进速度目标：600 RPM。
- 回线搜索速度目标：250 RPM。

### 9.7 左/右方向

`side=+1`：左移。
`side=-1`：右移。

方向参数同时影响：

- 横移给定。
- 回移给定。
- 里程完成判据。

### 9.8 看见线提前结束

`STRAFE_BACK` 必须已经回移至少 75% 横移距离，才允许“看见线就结束”。
避免宽障碍刚开始回移时还看得见线，导致零距离跳回。

### 9.9 里程计

默认：

```text
kodo = 221 / 1000 mm per (RPM*s)
```

含义：

```text
位移 mm = 轮速积分 RPM*s * kodo
```

按 152 mm 轮径、36:1 减速比估算：

```text
pi * 152 / 36 / 60 ≈ 0.221
```

必须现场标定。

### 9.10 标定命令

```text
avoid odo
```

清零前向积分。

然后遥控直行一段，量实际毫米数：

```text
avoid calib 1000
```

设置：

```text
avoid shift 300
avoid fwd 450
avoid app 300
avoid side left
avoid unit cm
```

### 9.11 无传感器走流程

```text
avoid run
```

下一次巡线循环强制进入 STOP。
用于先验证方向、距离、状态机和超时。

### 9.12 持久化边界

掉电保存：

- kodo。
- shift。
- fwd。
- side。

不保存：

- app。
- unit。
- on/off。
- 当前状态。

所以每次上电要确认：

```text
avoid status
```

### 9.13 安全兜底

- 任一段 8 秒超时：ABORT，车停。
- 离开巡线：取消。
- `chassis stop`：取消并保护。
- `avoid off`：立即取消。
- 轮组目标归零，闭环刹车。

### 9.14 避障现场验收

1. 车轮离地，`avoid run`。
2. 看状态顺序。
3. 看四轮电流方向。
4. 落地后手推车测实际横移。
5. `avoid calib` 标里程计。
6. 障碍物前验证三帧触发。
7. 改变障碍宽度验证 75% 条件。
8. 故意挡线验证 ABORT 停车。
9. 最后才让它自动触发。

## 10. 机械臂总体结构

### 10.1 关节组成

### 10.2 上电姿态

星呗舵机默认上电转到 1500。
你拆过肘关节，所以肩会带着臂动，肘有相对前伸。

### 10.3 关节限位

默认：

- 肩：1400～1600。
- 肘：1400～1600。
- 夹爪：1000～2060。

500～2500 对应 0～270 度。

大幅动作前：

```text
joint limit shoulder 500 2500
joint limit elbow 500 2500
```

### 10.4 夹爪

- PE13。
- TIM1_CH3。
- 50 Hz。
- 500～2500 us。

默认：

- 1100：张开。
- 1450：闭合。

命令：

```text
joint gripper 1100
joint gripper 1450
pick open 1100
pick close 1450
```

### 10.5 关节点动

```text

joint gripper 1450

```

### 10.6 总线舵机在线

- `servo_online()` 来自最近一次成功查询/响应。
- `servo_poll()` 会轮询位置。
- `pick learn` 和示教读点依赖位置回读。

### 10.7 配置模式

- 禁止运动。

退出：

### 10.8 舵机故障检查

## 11. yaw 双环与编码器

### 11.1 控制帧

- CAN2。
- 控制 0x1FF。
- 反馈 0x208。
- ID4。
- 电压 ±25000。
- 数据第 6～7 字节。

### 11.2 默认限位

- 左：ECD 1260。
- 右：ECD 6478。
- 一圈：8192。
- 0～8191。

限位区间不跨 0。

### 11.3 默认输出

- 电压限幅：8000。
- 位置环速度上限：500 RPM。
- 命令保持：10000 ms。
- 反馈超时：100 ms。
- 零输出保活：50 Hz。

### 11.4 默认增益

位置环：

- Kp=40。
- Ki=0。
- Kd=5。
- MaxOutput=500。

速度环：

- Kp=198。
- Ki=0。
- Kd=13。
- MaxOutput=25000。

未整定。
现场必须小步调。

### 11.5 方向标定

```text
yaw probe
```

过程：

1. 门控检查。
2. 必须在线。
3. 断环。
4. 正电压 4000。
5. 持续 150 ms。
6. 停 60 ms。
7. 看 ECD 位移。
8. 位移 >=3 判方向。

保护：

- 离任一限位不到 150 ECD 不推。
- 推的过程中进入保护带也立即停。

### 11.6 probe 没动

检查：

1. 24V。
2. ID4 灯。
3. `can stat` c2。
4. `yaw status` on。
5. 是否被限位门控。

调大 `yaw limit` 不会改变 probe 的 4000 上限。

### 11.7 手动方向

```text
yaw dir 1
```

如果一动就 `fault=1`：

```text
yaw fault clear
yaw dir -1
```

### 11.8 位置目标

```text
yaw target 3000
yaw step 100
```

目标会夹到 1260～6478。

### 11.9 双环计算

1. 位置环输入：ECD 转角度。
2. 输出：速度参考 RPM。
3. 速度环输入：GM6020 speed_rpm。
4. 输出：电压 PID 值。
5. 乘方向符号。
6. 边界检查。
7. 限幅。
8. 写 0x1FF。

### 11.10 长间隔微分保护

`dt > 6 ms` 时跳过本周期微分。
避免读舵机、写 Flash 后速度环被踢。

### 11.11 失控保护

条件：

- 本次命令后还没朝目标正确动过。
- 转速绝对值 >=15 RPM。
- 误差比首次反向运动时又增加 >=30 ECD。

动作：

- fault=1。
- 立即零输出。
- PID 清零。
- 命令拒绝，直到 clear。

### 11.12 反馈丢失

- 100 ms 没有新反馈。
- 普通命令：零输出，不锁故障。
- 回放且 yaw 参与：fault=2，流程 ABORT。

### 11.13 边界方向

`out*dir>0` 表示电压会让 ECD 增大。

- 到右界：禁止继续增 ECD。
- 到左界：禁止继续减 ECD。
- 允许往回。

### 11.14 yaw 调参顺序

1. `yaw probe`。
2. `yaw step 50`。
3. 看 `yaw status` 的 err/spd/out。
4. 先降速度上限：

```text
yaw speed 100
```

5. 再调位置环。
6. 最后调速度环。
7. 不自动整定。

### 11.15 yaw 过零现场验证

机械限位不跨 0，但 `total_ecd` 仍必须正确。
验证方法：

1. `yaw monitor`。
2. 手动从 8000 推到 0。
3. 看 round 和 total。
4. 再推回。
5. 确认 total 单调。

本轮已修“前 50 帧重锁原点”导致的跨圈丢失。

## 12. 拖动示教

### 12.1 状态机

```text
IDLE
READY
RECORD
SAVED
PLAYBACK
ABORT
```

### 12.2 按键

- 短按。
- 双击。
- 三击。
- 长按 2 秒。
- 长按 5 秒。

扫描周期约 3 ms，由机械臂任务驱动。
KeyTask 只负责灯和蜂鸣器。

### 12.3 状态映射

- IDLE + 长 2：READY。
- READY + 短按第一次：设原点。
- READY + 短按第二次：RECORD。
- RECORD + 短按：插关键点。
- RECORD + 双击：保存，SAVED。
- SAVED + 双击：PLAYBACK。
- PLAYBACK + 短按：停。
- 长 2：退出。
- SAVED + 两次长 5：删除确认。
- 三击：死程序启停。

### 12.4 灯语

- 绿：IDLE。
- 蓝：READY。
- 红：RECORD。
- 黄：SAVED。
- 青：PLAYBACK。
- 紫闪：ABORT。

状态变化蜂鸣 60 ms。

### 12.5 采样

- 20 Hz。
- 50 ms/tick。
- 512 点。
- 位移阈值：

```text
yaw 4 ECD
肩 5 us
肘 5 us
夹爪 10 us
```

### 12.6 暂停点

连续 4 tick 没有新点，补一个保持点。
保证回放时间不丢失。

### 12.7 保存内容

每个点 10 字节：

```text
yaw_ecd int16
shoulder uint16
elbow uint16
gripper uint16
dt50 uint8
reserved uint8
```

### 12.8 回放

1. 先回 pt0，最多 800 ms。
2. yaw 到位或超时 1500 ms 后继续。
3. 按 dt50 插值。
4. 肩肘舵机内部走线。
5. 夹爪按点设置。
6. yaw 由位置环跟随。
7. 自然结束精确走最后点。
8. 手动停止读当前位置并保持。

### 12.9 yaw 不参与回放

如果：

- 6020 离线。
- 方向未标定。
- 故障。

则肩肘流程照跑，yaw 不动。
如果 yaw 原本参与但中途丢反馈，流程 ABORT。

### 12.10 示教现场最快流程

1. `mode manual`。
2. 放宽关节限位。
3. 长按 2 秒。
4. 拖到 READY 位置。
5. `pick learn 0`。
6. 拖到 EXTEND。
7. `pick learn 1`。
8. 拖到 GRAB。
9. `pick learn 2`。
10. 拖到 RETRACT。
11. `pick learn 3`。
12. 拖到 RELEASE。
13. `pick learn 4`。
14. `pick save`。
15. `pick run`。

比完整录一段 512 点轨迹更快。

### 13.1 五个路点

- RELEASE：1333/1500，夹爪 1100。

### 13.3 `wp` 命令

```text
wp 0 1500 1500
wp 1 1700 1900
wp 2 1700 1900
wp 3 1350 1300
wp 4 1500 1500
```

优点：不依赖舵机位置回读。

### 13.4 `pick` 命令

```text
pick status

pick auto on

pick apply
pick save
pick run
```

### 13.5 遥控触发

巡线中：

```text
|ch4| 从 <300 变成 >=300
且距上次触发 >=1200 ms
```

触发：

- 停车。
- `arm_busy=1`。
- 机械臂任务执行 `pick_run`。
- 再触发停止。

### 13.6 视觉协议

UART8/PE0，115200。

帧：

```text
AA xH xL yH yL flag BB
```

- x：横向像素偏差。
- y：竖向像素偏差。
- flag：目标有效。

### 13.7 固定深度

视觉没有 Z。

代码：

```text
前向距离 = vis_depth_mm
高度 = cam_dy_mm - y_px * k
yaw修正 = x_px * yawk / 100
```

默认：

- depth=250 mm。
- k=1.5 mm/px。
- dy=0。
- yawk=0。

### 13.8 为什么 depth 不能是 300

L1=L2=150。
300 是臂全长，横向余量为零。
目标稍有横向偏差就够不到。

250 时理论横向余量约 147 mm。

### 13.9 四点标定

```text
ik learn sh0
ik learn sh90
ik learn el0
ik learn el90
```

含义：

- sh0：大臂水平。
- sh90：大臂竖直。
- el0：两连杆共线。
- el90：肘相对大臂 90 度。

四点齐了 `ik_valid=1`。

### 13.10 快速标 Z

1. 树前停车。
2. `vis` 记录 x/y。
3. 长按进示教。
4. 手拖夹爪对准果子。
5. `pick learn 1`。
6. `ik learn here`。
7. `ik save`。
8. `pick save`。

`ik here`：

- EXTEND 姿态正运动学 → fwd → depth。
- 有视觉帧时 → dy。

### 13.11 验证 IK

先不看视觉：

```text
ik xy 200 100
```

日志会打印反算出的肩肘脉宽。
让舵机走到该脉宽，测量夹爪实际位置。
目标：

- 前向误差尽量小于 20 mm。
- 高度误差尽量小于 20 mm。
- 两侧解唯一，肘取向上。

### 13.12 视觉验证

```text
pick vis 100 -50
pick apply
pick run
```

检查：

1. 目标帧是否新鲜。
2. `ik vis` 是否 CLAMPED。
3. 肩肘是否到预期。
4. yaw 是否需开 `yawk`。
5. 实际果实是否在夹爪口内。

### 13.13 什么时候需要动车

只转 yaw + 伸臂不够的情况：

- 横向像素 >=160。
- IK 打印够不着。
- yaw 超出机械行程。
- 固定深度误差超过果实/夹爪容差。

先挪车，不要硬伸。

## 14. 片内 Flash 与掉电保存

### 14.1 为什么不用 W25Q64

当前主流程已改为片内 Flash。
W25Q64 驱动保留，但 main 的初始化注释掉。
不要把 W25Q64 当当前轨迹存储。

### 14.2 A/B 槽

- A：0x080C0000。
- B：0x080E0000。
- 单扇区 128 KB。
- 镜像 v3。
- magic 0x41544C33。
- CRC32。

### 14.3 镜像布局

```text
0..15   头
16..79  标定 64 B
80..    轨迹点，每点 10 B
```

### 14.4 标定块

- 连杆长度。
- 四点 IK。
- 固定深度。
- 像素比例。
- 高度偏置。
- yawk。
- 夹爪开合。
- 关节限位。
- yaw 方向、限幅、增益。
- 底盘方向符号。
- 避障里程计、距离、方向。

### 14.5 写流程

1. 禁止巡线中写。
2. 冻结底盘。
3. yaw 零帧。
4. 延时 40 ms。
5. 擦另一个槽。
6. 32 字节编程。
7. 读回 memcmp。
8. 恢复。

### 14.6 CPU 停顿

H7 Flash 擦写时 CPU 取指停顿。
估 1～2 秒，未实测。

现场：

- 写 Flash 时车必须静止。
- 机械臂保持。
- 不操作遥控器。
- 看串口保存结果。

### 14.7 A/B 回退

加载：

1. 校验两槽 CRC。
2. 选 seq 较大的有效槽。
3. 新槽坏则用旧槽。
4. 逐字段校验标定。
5. 不因 IK 未标定而丢掉整套限位。

### 14.8 Flash 自检

```text
flash test
```

会：

- 写 4 个合成点。
- 读回。
- 擦测试槽。
- 恢复原轨迹。

期望：

```text
flash test PASS
```

### 14.9 保存边界

- `pick save`：轨迹+标定。
- `ik save`：标定，必要时只有标定镜像。
- `teach erase`：删轨迹，保留标定。
- `avoid app/unit`：不保存。
- `chassis map`：`pick save` 后保存。

## 17. 下午现场调试剧本

### 17.1 阶段 A：只接调试口

目标：确认电脑、烧录、串口、Flash。

动作：

1. 接无线 DAP。
2. 运行 `flash_console.py go`。
3. 看启动横幅。
4. 发 `diag`。
5. 发 `flash test`。

通过标准：

- 有启动日志。
- `flash test PASS`。
- 控制台命令有回复。
- `LOG drop` 不持续增长。

失败处理：

- 无串口：换 COM 或板载 USB。
- 烧录失败：检查 SWD、电压、hex 哈希。

目标：四个轮组反馈。

动作：

1. 轮子离地。
2. 接 24V。
3. 看 `[CAN]`。
4. 发 `chassis status`。

通过标准：

- 四个 on=1。
- ID 4/2/3/1。
- c1 rx 增长。

失败处理：

- 全 on=0：查总线供电和接线。
- 单个 on=0：查该 ID。
- rx 有但 on=0：查过滤和回调。

### 17.3 阶段 C：单轮方向

动作：

```text
chassis motor 0 800
chassis motor 1 800
chassis motor 2 800
chassis motor 3 800
```

记录：

## 19. 已知限制与不要做的事

### 19.1 不要自动整定 PID

现场时间不够。
自动整定会引入新的失效模式。
先手动小步。

### 19.2 不要改 CAN 位定时

当前 1 Mbps。
已按 H7 时钟配置。
没有证据说明需要改。

### 19.3 不要改 0x1FF/0x208

这是 6020 已验证协议语义。
不要改成 0x1FE。

### 19.4 不要同时改多个变量

一次只改：

- 一个 ID。
- 一个方向符号。
- 一个 PID 参数。
- 一个阈值。

每次记录前后串口。

### 19.5 不要忽略日志丢弃

`drop` 增长说明你看不到完整现场。
先降打印量。

### 19.6 不要用测试通过代替硬件通过

主机测试只能证明逻辑。
所有硬件项必须串口/CAN/实物确认。

### 19.7 不要花时间修历史乱码

`chassis_task.c` 等文件有旧编码问题。
只要新代码清楚、能编译即可。

### 19.8 不要在巡线中写 Flash

CPU 会停。
代码已拒绝，但不要绕过。

### 19.9 不要默认视觉存在

没有视觉电脑也能用死程序。
视觉帧超过 2 秒会自动退回示教路点。

### 19.10 不要一次上车就全开

先 CAN，再单轮，再遥控，再巡线，再避障，再机械臂，最后视觉。
