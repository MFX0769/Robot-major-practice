## 三、架构 v2 蓝图（我作为 owner 的重构方案）

### 3.1 目标
1. task 只做调度，业务下沉到模块——"task 里看到的是状态机，不是业务"
2. 参数一处可寻：`Application/config.h` 只留开关，数值参数全部进 `Module/xxx/xxx_param.h`
3. AI/人改参数时 grep 一跳即达；杜绝"改了 A 条件结果走的是 B 分支"
4. CAN/串口性能拉满：CAN 1Mbps 标准帧、聚合发送；串口 DMA 空闲中断 + 帧解析零拷贝

### 3.2 目标结构（在现有仓库内演进，不推倒重来）
```
Application/          # 只留调度（每文件 ≤150 行目标）
  robot_task.c        # 顶层状态机：BOOT→PROTECT→MANUAL→AUTO(巡线任务)
  arm_task.c          # 机械臂状态机：PROTECT/IDLE/HOME/MANUAL/DEMO/TEACH/PLAY/AUTO
  control_def.h       # 全局模式枚举+互斥宏（唯一真源）
Module/               # 新建：硬件无关业务
  line_follower/      # line_follower.c/h + lf_param.h
                      # 输入：8ch 模拟量/GPIO；输出 {vx_ref, wz_ref, confidence}
                      # 内部：质心估计→置信度→转弯状态机(45°/90°/直角/丢线)
  obstacle/           # obstacle.c/h：接近传感器去抖 + 绕行策略输出
  arm_ctrl/           # arm_ctrl.c/h：关节抽象（type: 6020/xb_servo/pwm_servo）
                      #   joint_set_deg(joint, deg, ms) —— 上层只说关节和角度
  mission/            # mission.c/h：已知地图=航点段表 {类型,长度,速度}
                      #   段类型：STRAIGHT/TURN_45/TURN_90/AVOID/STOP
Protocol/             # 驱动（已有，微调）
  prot_rm_motor.c     # 6020+2006 统一（含速度/电压模式）
  prot_xb_servo.c     # 串口舵机（待激活）
  prot_8irtraking.c   # v2：UART 流式 + GPIO 双模式，模拟量透传
Bsp/                  # 不动
```

### 3.3 交换契约（防"看漏条件"的关键）
- 模块间**只通过头文件里的类型和函数交互**，禁止 extern 散装全局变量跨模块读业务状态
- `control_def.h` 定义所有模式枚举；`chassis_mode` 与 `ctrl_mode` 严格分离（6 月已纠正的原则，代码化）
- 每个模块头部 10 行文档：输入/输出/参数在哪/谁调用

### 3.4 实施顺序（明天实验后执行）
1. 底盘 CAN 收敛 + shoot/gimbal/ui/fric 死代码清除（无硬件依赖，最先做）

## 四、疑问答复

- **CAN 并联**：CAN 本来就是总线拓扑，全部节点并联挂 CANH/CANL 再进 TJA1050，1Mbps 标准帧完全合法。你听说的"不能并联"不适用于 CAN（可能是 UART 或电源的坑）。达妙板收发器型号明天看丝印。
- **舵机"两个接口都能 PWM"**：客服话术不可信。手册证据：串口版和 PWM 版是两条独立产品线；总线舵机的双 5264 是级联口。明天实验定论。
- **"捡的板 B2B 坑"**：v2 不依赖任何"陀螺仪 0x018"外挂——达妙板 BMI088 上车后这条不确定性链路整体拆除。
