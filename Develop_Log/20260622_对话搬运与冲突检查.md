# 2026-06-22 对话搬运与冲突检查

## 目的

把近期关于机械臂、通信、标定、巡线和调试工具的高价值结论，整理成可继续继承的开发记录。

## 已确认的结论

### 1. 机械臂构型

- 机械臂可按 `底座 yaw + 肩关节 + 肘关节 + 末端夹爪` 来抽象。
- 适合使用 DH 参数法做简化建模。
- 逆解可先按 4 轴几何闭式解处理，不必先引入复杂规划框架。
- 末端姿态要求不高时，视觉只需要给出末端 `XYZ` 即可。

### 2. 控制与平滑

- 机械臂的目标值不应直接阶跃下发。
- 参考代码中的平滑思路本质上是 `ramp_calc` 斜坡限幅加三次轨迹插值。
- 当前更适合的方案是：逆解后先做关节角限位，再做步进平滑，最后转成 PWM 脉宽输出。

### 3. 舵机与使能

- 当前方案是 **PWM 舵机**，不是总线舵机。
- 舵机控制应与供电使能/失能分开封装。
- 供电侧建议保留 MOSFET 或继电器断电保护，防止 PWM 或机构异常时继续受力。
- 舵机没有额外位置反馈时，标定只能依靠开环扫脉宽 + 目测 + 机械止挡确认。
- 开发阶段可直接用 Keil Debug 修改全局变量完成单关节标定。

### 4. 通信与调试

- 当前最优先风险仍然是通信链路。
- 明天或返校后应优先验证 `CAN` 和遥控串口，再验证机械臂。
- 逻辑分析仪比 USB CAN 更适合当前阶段，因为它能直接看 PWM、串口和 CAN 的波形异常。
- 任意 H7 板都可以先做通信烟雾测试，但要根据具体板子的引脚和外设重新配置。

### 5. 巡线算法

- 现有巡线不是单纯的大于小于比较。
- 当前实现是先对 8 路灰度传感器做阈值判定，再做加权平均得到 `position`。
- 这个 `position` 再进入底盘 PID，生成 `wz_ref`。

## 建议放入代码的接口边界

### Application

- `arm_task`：机械臂状态机、流程编排、视觉目标接入。
- `arm_ik`：逆解、关节限位、轨迹平滑、目标修正。

### Protocol / Driver

- `prot_servo` 或等价驱动层：角度到脉宽映射、脉宽限幅、方向反转、目标值下发。
- `servo_enable / servo_disable`：供电使能控制。

### BSP

- `bsp_pwm`：定时器 PWM 输出封装。
- `bsp_gpio`：舵机供电开关或保护信号控制。

## 标定建议

1. 先只标定单个关节。
2. 在 Keil Debug 下修改全局变量，逐步调整 `pulse_zero`、`pulse_min`、`pulse_max`、`direction`。
3. 单关节确认后再做整臂联动验证。
4. 避免把目标打到肩肘接近共线的危险区。

## 与旧文档的冲突检查

### 1. `20260608_方案讨论.md`

- 旧文档写过“必须用总线/串口舵机（有位置反馈），不要用普通 PWM 舵机”。
- 这一条和当前结论 **严重冲突**。
- 当前已明确：项目采用 PWM 舵机，且外部控制阶段按开环标定处理，必须保留供电使能/失能。

### 2. `20260608_方案讨论.md`

- 旧文档写过“位置环 PID 足够，不需要复杂控制”。
- 这条 **不算严重冲突**，但需要改写语义。
- 当前更准确的表述是：舵机内部位置控制由舵机自身完成，外部控制器只做目标角度生成、限位和平滑。

### 3. `20260610_机械模型到位.md`

- 旧文档中的 COM 自动化 SolidWorks 尝试失败、转而等待手动导出 URDF 或量测轴线，这与当前结论 **不冲突**。
- 当前仍建议以实物测量和标定为主。

### 4. `tool_dev_log.md`

- 逻辑分析仪与调试工具链配置与当前结论一致。
- 其中 `nanoDLA` 作为波形排障工具，和当前“先查通信、再查 PWM”的思路一致。
