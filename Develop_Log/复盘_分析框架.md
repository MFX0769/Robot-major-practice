# 复盘分析框架

数据源：`对话流水_完整合并.txt`（376KB，1309 条消息）+ `Develop_Log` 6 份 + 作者补充的时间线/情绪记录  

---

## 一、每个事件的分析维度（7 层透镜）

每段"事件"（从提出问题到解决/放弃的完整周期）依次通过以下 7 个透镜分析：

### A. 基本面

| 字段 | 说明 |
|------|------|
| 时间 | 事件起止时间 |
| 问题描述 | 当时面对的现象 |
| 当时判断 | 对话原文中我/你对根因的猜测 |
| 实际根因 | 事后验证的真正原因 |
| 耗时 | 从开始到解决的墙壁时间 |
| 绕路标记 | 这一步是否绕路了？如果是，绕了多远？ |

### B. 归因透镜（归因理论）

**目的**：区分"这是我的问题"和"这是系统/环境的问题"

| 字段 | 说明 |
|------|------|
| 当时的归因方向 | 对话原文中你归因于自己还是归因于外部？（引原话） |
| 实际归因 | 内部（自己的判断/代码/知识不足） vs 外部（工具/硬件/时间/信息缺失） |
| 归因修正 | 如果重新归因，结论会不同吗？ |
| 对自己公平吗 | 这个归因是否把自己的责任放大了？ |

**为什么需要这个维度**：人在高压下会自然地把失败归己、成功归外。这次反过来——大量失败是外部因素，但当时的你不会知道。

---

### C. 决策退化检验（时间压力决策退化）

**目的**：识别"如果给我正常时间，我不会做这个选择"的时刻

| 字段 | 说明 |
|------|------|
| 当时的选择 | 你做了哪个决策？（比如：换电调而不是查参数） |
| 另一个可能的选择 | 正常情况下你会选什么？ |
| 什么压力让你做了这个选择 | （死线倒计时？凌晨困？AI 推动的？队友在等？） |
| 这个选择代价多大 | 时间 + 情绪成本 |

**为什么需要这个维度**：有些"错误决定"在 40 小时死线下其实是理性选择——因为不决策的代价更大。维度 C 帮你看清哪些是真的判断失误，哪些是被迫的选择。

---

### D. 假设锁定检查（确认偏误 + 沉没成本）

**目的**：找到"先入为主后，证据摆在面前也看不见"的时刻

| 字段 | 说明 |
|------|------|
| 当时的假设 | 最开始认定了什么？（比如："右前轮是机械卡死"） |
| 这个假设来源 | （上一轮排查残留？学弟说的？自己猜的？AI 提示的？） |
| 驳斥证据 | 期间有没有出现反驳这个假设的数据？如果有，忽略了吗？ |
| 为什么没注意到 | （疲劳？数据太多？工具不可信？信息呈现方式不对？） |
| 最早应该转向的点 | 回看时，哪一刻就已经说明假设可能是错的？ |
| 沉没成本 | 到转向时已经在这个方向上花了多少时间？ |

**为什么需要这个维度**：这是兜圈子的核心机制。很多时候不是"没找到根因"，是"找错方向后没及时掉头"。

---

### E. 奶酪对齐（瑞士奶酪模型）

**目的**：量化一次踩坑是由于多少人因/组织/工具层面的弱点同时对齐

| 奶酪层 | 对齐？ | 证据 |
|--------|--------|------|
| 代码不熟（半年没碰+学弟维护） | □ | |
| AI 多终端不一致 | □ | |
| 工具不可靠（GDB/Keil/OpenOCD） | □ | |
| 硬件故障 | □ | |
| 信息缺失（不知道某个文件/配置的状态） | □ | |
| 睡眠剥夺 | □ | |
| 情绪堆积 | □ | |
| 其他：__________ | □ | |

**为什么需要这个维度**：如果一层奶酪漏了，不会出事。多层同时漏才出事。这个维度的价值是——每次踩坑都不是"一个原因"，而是"所有原因刚好同时出现"。

---

### F. 情绪/心流定位

**目的**：沿着时间线画出情绪曲线，找到习得性无助的拐点

| 字段 | 说明 |
|------|------|
| 当前状态区 | 心流 / 焦虑 / 无聊 / 疲惫 / 麻木 |
| 关键证据 | 对话原文中体现状态的措辞（引原话） |
| 无助指数 | 1~5（1=主动排查中，3="先记录吧"，5="你决定吧"） |
| 上次正反馈是什么时候 | 离现在多久前有了一次成功的修复/确认？ |
| 正反馈间隔 | 上次成功验证 → 现在经过了多少事件？ |
| 情绪朝向 | 这个事件后是更积极了还是更消极了？ |

**为什么需要这个维度**：连续"修 A 冒 B"会产生现实层面的习得性无助。这不是心理问题，是问题队列太长的合理反应。记录正反馈间隔可以量化"为什么这个时刻特别崩溃"。

---

### G. 可复用信号（产出维度）

**目的**：每个事件产出一条将来可以直接用的判断规则

每条规则格式：
> **症状**：______________
> **第一反应**：______________
> **信号**：______________

例如：
> **症状**：开环直发 2000 能转，恢复 PID 闭环后不转
> **第一反应**：怀疑硬件（换轮子/换电调/查接线）
> **信号**：**先查 PID 参数限幅，再拆螺丝**

## 二、分析完毕后做的事件串联

每个事件独立分析完后，做两条跨时间线：

### 1. 归因漂移曲线

把所有事件的 B 维度（归因方向）按时间画出来：
```
外部归因比例
100% ┤
     │         ●
 80% ┤       ○   ○
     │     ○        ●
 60% ┤   ○            ○
     │ ○                ●
 40% ┤                      ○
     │                        ●
 20% ┤                          ●
     │
  0% └──────────────────────────→ 时间
                                  （每个点=一个事件，○=外部，●=内部）
```

**关注**：从什么时候开始你更多地归因于自己？这个转折点是不是跟某个工具背叛事件重合？

### 2. 无助感 - 正反馈间隔对照

```
无助指数 5 ┤
         │               🔴
      4 ┤         🔴        🔴
         │      🔴     🔴
      3 ┤   🔴              🔴
         │  🔴  ✅           🔴
      2 ┤✅        🔴  ✅
         │     ✅        ✅     🔴
      1 ┤                          ✅
         └────────────────────────────→ 时间
           ✅ = 正反馈（成功验证）
           🔴 = 事件结束时的无助指数
```

**关注**：如果两次正反馈之间相隔太久，无助感曲线是否必然攀升？这可以验证"不是人不行，是反馈周期太长了"。

### 3. 奶酪对齐次数统计

统计每个事件 E 维度对齐的奶酪层数：
- 1~2 层对齐 → 正常 debug
- 3~4 层对齐 → 困难 debug
- 5~7 层对齐 → 这次最多的状态

如果大部分事件都是 5+ 层对齐，那所有"我感觉自己在原地转"的感觉就有了量化解释。
