### 一、最值得抄的巡线算法（附关键代码要点）

#### 1.1 采样层：先让每个灯读得稳（A 级，两仓库源码直读）

- **选通式读法（helu33 `bsp_line.c`）**：3 根地址线选通道 + 1 根输出读电平，每次切通道后用 **DWT->CYCCNT 等 CHASSIS_MUX_SETTLE_US 微秒建立时间**，凑齐 8 路才原子发布一个 `published` 位掩码 + `scan_sequence` 序号 + 时间戳；上层用 `line_bsp_snapshot()` 检查数据新鲜度（超过 `CHASSIS_LINE_MAX_AGE_MS` 判无效）。要点：**巡线数据带时间戳与序号，控制环用"快照"而不是随手读 GPIO**。
- **双重读取（5ee511 `grayscale.c`）**：切通道 → `delay_us(GRAY_SETTLE_US)` → 读一次**丢弃**（比较器建立余量）→ 再 `delay_us(10)` → 第二次读取有效。对"边缘灯闪烁"类毛刺这是第一道闸。
- 写法细节：先写 AD2(MSB) 再 AD1、AD0，减少中间态跳变（5ee511）。

#### 1.2 单帧几何滤波：误触发的核心解药（A 级，helu33 `chassis_mission.c`）

`mission_line_error()` 是对"边缘某个红外灯闪烁导致误判断"最直接的答案——**一个掩码只有在"压线传感器数量 ≤3 且空间上连续"时才算有效**：

```c
/* 返回 1=有效并输出误差(mm)，0=无效 */
uint8_t mission_line_error(uint8_t mask, float spacing, float *error) {
    unsigned i, first=8, last=0, n=0; float sum=0;
    for (i=0;i<8;i++) if (mask & (1U<<i)) {
        if (first==8) first=i;
        last=i; n++; sum+=((float)i-3.5f)*spacing;   // 位置 = (i-3.5)*间距，8 路等权
    }
    if (!n || n>3 || last-first+1!=n) return 0;      // 空掩码/超过3个/不连续 → 无效
    *error=sum/(float)n; return 1;
}
```

- "不连续即无效"直接把**孤立跳变的边缘灯**（如 bit0=1 但 bit1~7=0，或 bit0/bit7 同帧乱闪）整帧拒收：拒收帧走"丢线分支"（见 1.4），而不是把 ±3.5 探针间距的大误差喂进 PD。
- 权重选型参考（B 级，两处独立印证）：8 路等权 `(i-3.5)*spacing`（helu33，mm 量纲）与非线性权重 `-40,-25,-12,-4,4,12,25,40`（lanq.me）、`+2.0,+1.4,+0.35,0,0,-0.35,-1.4,-2.0` 除以压线数（oshwhub）、`6.0,4.2,1.8,0,0,1.8,4.2,6.0` 不除以计数（5ee511，PD 增益里补偿）。**小误差线性段用等权/线性权重即可，外侧大权重只为远处猛拉**。
- 归一化校准（B 级，lanq.me）：开机每路采 32 轮、**剔除两端各 4 个值**用剩余 24 个求均值，得到该场地该路灰度的白/黑参考；上线前标定，不同场地不能共用一组默认值。

#### 1.3 时序确认与防重入（A 级，两仓库）

- **弯道触发确认 3 帧**（helu33）：`corner()` 特征 = 左半 4 路 ≥3 亮 且 中央 bit3/bit4 都亮 —— `count_bits(mask&0x0f)>=3 && (mask&0x18) && (mask&0x0c)==0x0c`；连续 3 帧满足才进 PRE_TURN，任何一帧不满足清零重数。
- **直角弯退出三保险**（5ee511 `empty.c track()`）：
  1. `TURN_MIN_FRAME=3`：转弯最少帧数，禁止过早退出；
  2. 退出需先 `armed`（原触发侧离开）再等**中央 D4/D5 连续 2 帧**捕线；
  3. 退出后 `TURN_EXIT_LOCKOUT_FRAMES=15` 帧防重入，防同一段线反复触发。
- 弯道触发条件本身：`一侧 ≥3 灯亮 && 另一侧 ≤1`（容忍竖线残留），比"外端灯亮就转"抗噪得多。

#### 1.4 丢线处理策略（A 级）

三套递进（按工程成熟度排序）：

1. **5ee511（简单直接）**：
   - 从未见过线 → 原地旋转搜索（`L=-SLOW, R=+SLOW`）；
   - 见过但丢线 → **惯性保持上帧误差** `error = g_last_valid` 继续打方向；
   - 全亮（cnt==8，路口/交叉）→ 误差取 0 直行。
2. **helu33（带符号搜索 + 兜底）**：丢线时目标速度降到 0.08 m/s 慢滑；`search_w()` 按上次误差符号给固定角速度 ±1.0 rad/s——**误差超过半个探针间距才转，误差居中=前方是缝隙，直行**；丢线计时 >0.20 s 直接进 FAULT 停车（已知短环线，宁可停不要飞）。
3. **oshwhub（B 级）**：八路全丢线时保持上一次偏差继续打方向，防路口/断线失控。

#### 1.5 误差 → PD 细节（A 级，helu33）

```c
m->line_error += dt/(0.02f+dt) * (error - m->line_error);          // 误差 EMA，τ=20ms
m->derivative += dt/(0.03f+dt) * ((line_error-prev)/dt - m->derivative); // 微分 EMA，τ=30ms
target_w = clamp(-kp*line_error - kd*derivative - kh*heading_error, -1.5f, 1.5f);
if (fabsf(line_error) < 0.5f*spacing)                              // 线居中时：
    m->heading_trim += dt/(2.0f+dt) * heading_error;               // 航向基准缓慢跟随陀螺（吸收零偏/比例误差）
target_v *= 1.0f - 0.3f*clamp(fabsf(line_error)/40.0f, 0, 1);      // 偏差越大越减速
```

- **灰度 PD + 航向项混合**：直线段 `kh*heading_error` 守航向，`heading_trim` 用 τ=2 s 低通让"线是长期真值"；这就是 lanq.me 说的"直线守航向、弧线看灰度"的工程实现。
- 输出端再加 `w` 斜率限制（`line_angular_acceleration`，直线用更缓的档）：**一个探针间距的误差阶跃（11 mm）不会变成 jerk**，helu33 实测 10-28 场地日志：不设它，直线上的 yaw 抖动让云台误差翻倍。
- 5ee511 侧：`steer_out = kp*err + kd*diff`（kp=20, kd=10, 限幅 ±200 mm/s），弯道减速 `base = FAST*(1-|err|/12*0.7)`，最低轮速地板 50 mm/s 防内轮停转。

### 二、弯道/直角弯转弯策略

#### 2.1 陀螺仪闭环方案（A 级，helu33 `chassis_mission.c`，首选）

四状态：`MISSION_LINE → PRE_TURN → TURN/REACQUIRE → (循环)，4×laps 弯后 FINISH`。

- **进弯前减速（梯形刹车）**：已知地图（上弯间距可测），直线段按剩余路程 `room` 计算 `target_v = min(v, sqrt(v_turn² + 2·decel·room))`，刹车末段额外保留 `v_turn·TURN_LAG_SEC + 0.04 m` 的"车身滞后余量"（车体响应有延迟，`TURN_LAG_SEC=0.20 s` 由场地日志标定）。
- **PRE_TURN**：触发确认后保持 `v=turn`、`w=0` 直走到 `sensor_ahead_m - radius_m - turn_lead_m` 处（传感器在车前、探头到轴心距离要补偿），`turn_lead_m = v_meas*(TURN_LAG_SEC + w_turn/(2·angular_acceleration))`。
- **TURN**：`target_w = min(v/radius, sqrt(2·angular_accel·remaining))`，`remaining = 90° - 已转角 - gyro_z*TURN_LAG_SEC`（提前刹角速度）；转到 80° 进 REACQUIRE。失败保护：转角 >130° 或 <-15° 或超时 5 s → FAULT。
- **REACQUIRE**：三条件全满足连续 3 帧才算上弯——线在中央 ≤1.5 探针间距、车身与新边方向差 ≤15°、角速度 <0.35 rad/s；期间线出现就灰度 PD + 新边航向项双修，找不到线就按上次误差符号 search_w，纯偏航就用 `-kh*new_edge_error` 拉回。
- **计圈/停车**：`corners ≥ 4×laps` 后按**实测触发点间距平均**外推终点距离，`sqrt(2·decel·remaining)` 减速停车（起点已在身后就立即停）。
- **底层融合**：`yaw_rate()` 陀螺有效用陀螺，否则 (Δd_r−Δd_l)/wheelbase/dt 用编码器差速推角速度，容许 ≤50 ms 的 IMU 掉线；陀螺毛刺限幅 `MISSION_YAW_CORRECTION_MAX=1.0 rad/s`（**一个陀螺 glitch 不能把车甩转**）。

#### 2.2 灰度触发开环方案（A 级，5ee511，最快平移）

触发（一侧≥3 另一侧≤1，加 1.3 的三保险）后**纯开环差速圆弧**：左转 `L=50, R=200 mm/s`，右转镜像；中央 D4/D5 两帧捕线退出并回 NORMAL PD（同帧生效，`g_prev_error=0` 防旧误差微分冲击）。直角弯表现可靠（2026-07 实车验证），但 45° 掰弯/不同车速下要重调内/外轮速配比——这正是用户"转弯参数粗糙"的来源：**开环配比只在特定车速和轮距下成立**。

#### 2.3 选型建议（C 级，综合推断）

- 短环线 + 已知地图：抄 **helu33 状态机骨架**（LINE/PRE_TURN/TURN/REACQUIRE/FAULT + 触发点间距自学习 + 计圈），转弯用陀螺角速度闭环而不是开环差速配比；45° 掰弯把 `90°` 目标角换成地图参数即可，状态机不用改。
- 传感器在车前：所有几何都要带 `sensor_ahead_m` 前置补偿（helu33 用 `sensor_ahead - radius - turn_lead`，且限制 `sensor_ahead < radius + turn*0.06` 防参数组合非法）。
- 差速比通用写法：`v_L = v - w*L/2, v_R = v + w*L/2`（mega_12800 `move()` 同式），弯道急慢交给 `w` 规划，不要手配左右轮速常数。

### 三、避障逻辑（接近传感器触发后的绕行路径）

找到的三种范式（按复杂度）：

1. **开环定时序列（A 级，mega_12800 `Drive.cpp obstacle_avoidace()`）**：
   ```c
   if (ranger.get_distance() < 26) {
       run_task_for(LeftTurnCallback, 170);   // 原地左转(定时)
       run_task_for(ForwardCallback, 700);    // 前进越过障碍
       run_task_for(RightTurnCallback, 100);  // 摆正(平行偏移)
       run_task_for(ForwardCallback, 1000);   // 沿旁路直行
       run_task_for(RightTurnCallback, 100);  // 摆回
       // ...之后回巡线
   }
   ```
   简单可靠但漂移随时序累积；**对已知地图固定障碍，把"定时"换成"里程/转角"就是可用方案**：`陀螺转角闭环替代定时转、编码器里程替代定时直行`。
2. **左右测距比较（B 级，汉斯期刊《无人配送小车设计》[^1]）**：SR04 装舵机上，<35 cm 触发，舵机转 0°/180° 比较两侧障碍距离，选远侧绕行；两侧均 <25 cm 则掉头。逻辑通用，对本车"单只 IO 接近传感器"降级为：**触发即默认向固定侧绕行（地图已知，绕行侧写死）**。
3. **任务级状态机（A 级，helu33 骨架复用，推荐）**：把绕障做成与转弯同构的状态链 `APPROACH →(触发确认) DODGE_OUT → DODGE_SIDE → DODGE_IN → REACQUIRE`：
   - 触发确认：接近传感器 IO **消抖（≥2 帧/20 ms）+ 里程窗口**（已知障碍大致位置，只有"接近该位置且 IO 触发"才认，排除误触发/行人闪过）；
   - `DODGE_OUT`：`w` 规划转一个固定角度（如 45°/90°）同时减速，用 `sqrt(2·α·remaining)` 同款梯形；
   - `DODGE_SIDE`：守临时航向（`heading_error = heading - dodge_heading`）走固定里程 = 障碍占线长度 + 余量；
   - `DODGE_IN`：反向转回原航向，直行回线区；
   - `REACQUIRE`：**直接复用 helu33 的 REACQUIRE**（找线 + 航向对齐 + 3 帧确认）回正线。全程不依赖看到障碍物的形状，只依赖里程计 + 陀螺 + 已知地图。
4. 2021 电赛 F 题国一（gogongxt，B 级）：三岔口/病房都是"特征点触发 + 状态机分支 + 记忆地图"思想，OpenMV 视觉巡线细节对本车不适用，状态划分思路可参考。

### 四、BMI088 姿态解算滤波选型（Mahony / EKF / VQF）

| 方案 | 来源 | 依赖 | H723 适用性 | 结论 |
|---|---|---|---|---|
| **Mahony 互补滤波（四元数）** | helu33 `gimbal/Algorithm/MahonyAHRS.c`（单文件，A 级实测：BMI088 恒温加热到 40℃ + 静止 14 s 测零偏，锁靶 mm 级）；oshwhub 用 5 ms 周期 Mahony + 0.5°/s 死区 + 1000 次开机零偏采样（B 级） | 无，单 .c/.h | 直接用 | **最省事，首选** |
| QuaternionEKF | WangHongxi2001/RoboMaster-C-Board-INS-Example（331★）；Apollo-kernel/CtrBoard_H7_IMU_BMI088 已把 EKF+Mahony 移植到 H723+BMI088（MIT，含 AC5/AC6 移植坑说明，B 级） | `pvPortMalloc` 托管 + CMSIS-DSP 矩阵函数（arm_mat_*），还要 DSP 加速 | 可用但移植工作量最大 | 精度上限最高，课设没必要 |
| **VQF** | 官方 [dlaidig/vqf](https://github.com/dlaidig/vqf)（326★，MIT）：**"Versatile Quaternion-based Filter"，Laidig & Seel 发表于 Information Fusion 2023**（doi:10.1016/j.inffus.2022.10.014）。主实现 C++（单 vqf.cpp），另有 Python/Matlab；支持 6D（无磁）与 9D 融合、**陀螺/加速度/磁力计可不同采样率**、只有 2 个调参参数、内置陀螺零偏估计与磁干扰抑制。嵌入式 C 版：[DusKing1/vqf-c](https://github.com/DusKing1/vqf-c)（49★，MIT）：面向 Cortex-M4F/RISC-V，`#include "vqf.h"` → `initVqf(gyrTs,accTs,magTs)` → `updateGyr/updateAcc/getQuat6D`，无 RTOS/malloc 依赖 | vqf-c：纯 C 单文件，无外部依赖；**TODO 里写着还没接 CMSIS-DSP，性能未优化**，计算量明显大于 Mahony | H723 双精度/单精度 FPU 跑得动 | 能用、默认参数即合理；但对比 Mahony 没有明显性价比 |

**选型结论**：
- **底盘（本车真正需要的）**：其实不需要完整姿态解算——helu33 底盘只用陀螺 `gz` 积分 + 线上 `heading_trim` 慢速回正（τ=2 s），一个 BMI088/ICM 只读陀螺就够；要航向就加 Mahony。
- **要姿态（云台/机械臂）**：**最省事 = 抄 helu33 的 Mahony 全套**（MahonyAHRS.c + BMI088driver + 恒温加热 + 静止零偏校准），有实测背书。
- **H7_BSP 已用 VQF 的确认**：VQF 即上述算法，依赖很小（vqf-c 单文件、MIT、无 RTOS 依赖），H723 上可行；若追求省事和算力余量，Mahony 是更轻的选择；若要零偏在线估计和默认参数即准，VQF 有优势。两者都远比 EKF 轻。

## 任务 2：星呗 SP 总线舵机双接口语义

**结论：两个 5264-3P 接口是"级联并联同一总线"（同一根半双工 UART 信号线的进/出，类似 CAN 进出），不是 PWM 输入口。未找到任何"SP 系列支持 PWM 输入"的证据；PWM 在同店是另一个独立 SKU（独立产品），不是 SP 的接口模式。**

证据链（按强度）：

1. **商品封面实拍（A 级，图片直读）**：SP-30S 封面明确写"高精度**串行总线舵机**｜金属齿轮｜**指令控制**｜源码例程｜智能防堵｜**串口指令控制**｜**舵机角度回读**｜电压温度反馈"，机身丝印"**BUS SERVO / 串行总线舵机 / SP-30S**"。全文零 PWM 字样。
   封面图：https://img.alicdn.com/bao/uploaded/i2/2206842090775/O1CN01c2b5PU1Hb063ZgTS3_!!2206842090775.png （淘宝商品图，经 [虎窝淘镜像页](https://tao.hooos.com/goods_8JRd7bbcnt9zkeqqw4TggMibt8-k5v00Gf8BpoDkbdCp.html) 获取，商品页标题"30kg串行总线舵机串口单轴SP-30S"）
2. **同店同品牌 PWM 是独立 SKU（B 级）**：京东同款星甲智能云台分"**【PWM舵机30kg】**"与"**【总线舵机30kg】**"两个 SKU（https://item.jd.com/10220551732443.html 与 https://item.jd.com/10220551732450.html）——PWM 与串行总线是**两条产品线**，SP 系列不带 PWM 模式。
3. **同品类双 3P 口语义一致（B 级，行业佐证）**：
   - 微雪 ST3215（同为 PH2.0-3P 双口串行总线舵机）Wiki 原文："**每个舵机上面有两个接口，可以将舵机串联起来使用**，理论上可以同时控制 253 个总线舵机"：https://www.waveshare.net/wiki/ST3215_Servo
   - FashionStar 串行总线舵机手册（接口同为 PH2.0-3Pin、UART/TTL 半双工）：其型号编码里 **PWM（P/A）是独立协议型号**，与 UART（U）并列而非共存：https://fashionstar.com.hk/wiki/servo/uart/datasheet/pdf/Fashion-Star-HX8-U29H-M.pdf
   - 飞特《通讯协议手册》：TTL 总线舵机为"**单总线（一条信号线分时复用发送与接收）**+ 三线物理连接，ID 0~253，广播 254"，多个舵机串联需先改 ID：https://www.feetech.cn/Data/feetechrc/upload/file/20240702/舵机协议手册-电位器版本.pdf
4. **使用方式佐证（B 级）**：星呗 6 轴机械臂套件（6 个总线舵机 + STM32，B 站有"开源 6 自由度机械臂"视频）为典型的串联级联拓扑，符合双口级联用法。

**未找到**：星呗/WebbotPi（星甲智能）官方 SP 系列说明书在线版（官网 webbotpi.com 无法访问，000 无解析；店铺页 xbrobot.taobao.com 需登录；商品详情文字页仅图片）。手册随货资料包发放（封面写"提供技术支持+多种源码例程"）。

**建议 5 分钟实测确认（C 级，操作建议）**：主控 UART 接 A 口给舵机发指令，示波器/逻辑分析仪探头搭 B 口信号针——若 B 口上能看到**同一串口波形**（直通），即级联并联实锤；再把第二个舵机接 B 口、只对 ID1 发帧，ID2 舵机（改 ID 后）若有应答则级联闭环。也可直接进店问客服一句"两个接口是不是串联通的、能不能接第二个舵机级联"，截图留档。
