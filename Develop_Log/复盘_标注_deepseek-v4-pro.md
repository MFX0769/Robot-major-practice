### E2. SBUS 解析器 DMA 长度 bug + 修复

#### A. 基本面

| 字段 | 内容 |
|------|------|
| 时间 | 06-22 深夜 ~ 06-23（从发现到修复约 30 分钟有效排查 + 之前的绕路） |
| 问题描述 | SBUS 遥控器接收机蓝灯常亮（物理连接确认），但 `wbus_rx_cnt` 恒为 0，所有 16 通道值全是 0 |
| 当时判断 | 第一轮：怀疑 BTB 连接器接触不良 → 重插 → 仍为 0。第二轮：怀疑波特率/DMA 配错 → 查配置 → 波特率对 |
| 实际根因 | `Comm/usart_comm.h` 定义 `DMA_DBUS_LEN=18`（老代码 DBUS 协议的 18 字节），但 SBUS 帧是 25 字节。DMA 只收 18 字节 → IDLE 中断调 `sbus_callback_handler(buf, 18)` → 函数第一行 `if(len < SBUS_FRAME_SIZE) return;` 即 `18<25` 恒真 → **从未真正解析过一帧** |
| 耗时 | ~30 分钟排查（不含 BTB 绕路） |
| 绕路标记 | 🔴 中度绕路 — BTB 连接器检查是因为之前 CAN 故障是真实的连接器问题，形成了锚定 |

**证据**：
- `20260624_nanoDLA接入与CAN分支合并.md` L55-56："SBUS 解析器 bug 修复... SBUS 一帧是 25 字节，DMA 缓冲区只给了 18 字节"
- `20260624_nanoDLA接入与CAN分支合并.md` L83："SBUS 真正的根因：DMA 缓冲区长度配置错误（纯软件 bug）"
- `复盘分析_20260622_25.md` L83-88 记录了 BTB 绕路
