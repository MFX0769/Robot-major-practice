## 二、任务定义与验收门（2026-11-23 改写）

### 闭环等级（以后禁止混用）
- **L0 构建**：编译通过、hex 已更新。
- **L1 单向链路**：只证明 TX 或 RX 的一个方向，例如 COM95 收到 `U7_FROM_STATUS`。
- **L2 原始接收**：MCU 能收到预期原始字节，计数和原始内容均可核对。
- **L3 协议闭环**：A/D 帧字段、计数、`state/position` 与输入一致，持续运行无 ORE/HAL_BUSY。
- **L4 物理功能**：真实模块遮挡实验通过，通道映射和实际行为一致。
- **L5 系统联调**：真实执行机构/整车业务使用数据并达到功能目标。

**“编译成功”“HAL_OK”“收到测试字符串”都只能记为对应等级，禁止写成整个任务闭环。**

### 任务1：H723 基座 bring-up（主体已完成，保留优化债）
- BMI088：原厂与迁移工程均已出姿态数据，迁移工程记录为 1040fps；当前达到板级验证，不代表 P0 优化完成。
- CAN：只完成 CAN1↔CAN2 板级互收；实际电机控制未验证。
- 遗留：taurus 的 CAN 时钟/波特率复核；BMI088 DMA burst、PE12 DRDY、温控降频与超时保护。

### 任务2：U7 巡线（当前唯一主线）
按以下顺序推进，不允许跳级：
1. **CH343 模拟器闭环（目标 L3）**：恢复巡线接收/解析，移除 `U7_FROM_STATUS`；PC 在 COM95 发送一组已知 `$A/$D` 帧，MCU 的 `rx`、8 路字段、`state/position` 必须与输入一致。
2. **真实模块闭环（目标 L3）**：模块 5V 供电，TXD→PE7、RXD→PE8、共地；U7 线上只发合法协议命令，确认持续收到真实 A/D 帧。
3. **遮挡验收（目标 L4）**：逐个遮挡探头，确定 x1～x8 与物理位置映射，并验证黑线移动时 `position` 方向正确。
4. 若使用帧率作验收，必须同时记录**字节数、帧数、采样时长**；旧日志的“1204 对/s@115200”与 ASCII 帧带宽不符，复核前不得作为基准。

### 任务3A：串口总线舵机 + 可调电源（巡线闭环后开始）
- 先确认型号、额定电压、协议、半双工方式和接口分配，再上电。
- 独立台架顺序：读型号/角度应答 → 小角度运动 → 角度回读一致 → 接入业务。
- 电流记录：静态、空载运动、受限短时堵转三档；记录电压、电流上限、持续时间，堵转必须受电源限流和机械安全约束。

### 任务3B：实际电机接入（与舵机分项验收，不再被“CAN 互收”替代）
- 先完成 taurus CAN 波特率复核，再核对电机型号、ID、协议、24V 供电和终端电阻。
- 验收顺序：读状态/反馈 → 单电机低风险使能 → 指令与反馈一致 → 掉线/停机保护。

### 任务4：性能优化（基础外设闭环后）
- BMI088 P0：DMA burst、DRDY、数据新旧程度（时间戳/序号/年龄）、≥1000Hz 融合输出稳定性、温控降频。
- CAN 优化必须建立在实际电机基准数据上；没有 baseline 不启动泛化优化。

## 四、上一轮审计：为什么拖久、到底卡在哪里（2026-11-23）

### 4.1 主结论
**不是巡线模块本身难，也不是硬件都坏了；主要是实验配置、变量和结论等级失控。** 最终证据是：taurus 的 UART7 被临时改成 921600 后未复原，而 PC 一直按 115200 读取；改回后 COM95 立即收到 2048 字节测试数据。这是 TX 链路的根因，但完整巡线 RX/解析仍未验收。

| 失控点 | 日志证据 | 造成的后果 | 新规则 |
|---|---|---|---|
| 临时配置没有台账和复原点 | D3 才发现 taurus U7 仍为 921600 | 后续 6+ 轮在错误前提上排查 | 每次改动登记旧值/新值/复原条件；烧录前核对配置快照 |
| debug 与业务抢同一 UART | 第二十二节发现 `dbg_print` 使用 huart7 | 模块收到调试垃圾，合法启动命令被淹没 | U7 只跑巡线协议；debug 固定 U10 |
| 多变量同时变化 | 波特率、IRQ、ORE、HDSEL、轮询、软 I2C、供电和接线连续叠加 | 无法知道哪个改动产生哪个现象 | 一次实验只改一个自变量，并固定接线拓扑编号 |
| 过早宣布“软件全通/真正根因” | 第十六、十七、二十二、二十四、二十五节均有后文推翻前文的定谳 | 错误结论引导下一轮，用户也被告知错误方向 | 按 L0～L5 记录；“根因”必须能解释全部证据并被对照实验复现 |
| 把 TX 测试当成巡线闭环 | D4 只收到 `U7_FROM_STATUS` | 实际模块 RX、A/D 解析和位置解算仍未做 | 任务2 必须达到 L3/L4 才算完成 |
| 编辑方式引入二次故障 | Python 改 CRLF+中文 C 源码，文件重复/截断两次 | 排查通信之外又修文件损坏 | C 源码只用 Edit/Write；禁止 Python 字符串注入 |
| 超时后没有自动退回基线 | 1 小时预算严重超出，直到用户提议原厂 A/B 才突破 | 假设堆叠代替对照实验 | 单假设最多 20 分钟或 2 次烧录；无新证据立即退回最小对照 |

## 七、实验与烧录纪律（下一轮硬性执行）

1. **一次实验一个自变量**：代码、接线、供电、串口工具不得在同一轮同时变化。
2. **单假设止损**：20 分钟或 2 次烧录仍无新增证据，立即停止该路线，回到最小已知良好对照；不得连续堆第三个假设。
3. **每次烧录必登记**：实验编号、时间、拓扑、代码版本、唯一改动、动机、预期、烧录命令、原始输出、结果等级、是否复原。
4. **配置台账**：临时改波特率/引脚/任务开关时，同时写下旧值、新值和恢复条件；下一轮烧录前核对。
5. **接线拓扑编号**：T1（CH343 模拟器）和 T2（真实模块）分开记录，禁止跨拓扑直接比较结论。
6. **最小系统优先**：若连 `[SYS]` 都消失，先恢复系统健康，不再叠加外设排查。
7. **日志措辞**：只写已被证据支持的等级；观察、假设、根因、验收分栏，禁止反复使用无对照支撑的“实锤/最终”。
8. **既有禁令保持**：不开子代理；不用 Python 批量改 C 源码；debug 不走 U7；不用 openocd 读 RAM/寄存器。
9. **开发日志去向**：每次实验与烧录追加到 `Develop_Log/daily_review.md`；handoff 只保留下一次会话所需状态。
