# 20260620 课设小车代码迁移计划

## 目标

以最新比赛代码为主干，把课设小车的底盘、巡线、4 个 2006 电机和必要的调试链路接入进去，先保证能编译、能烧录、能继续迭代。

## 总原则

1. 先保证主干稳定，不先做大范围裁剪。
2. 课设逻辑只接一条主链路，避免多入口同时改同一份状态。
3. 先修编译错误和明显 warning，再谈运行时优化。
4. 日志保留，但只做最小观测，不干扰主控制链路。
5. 旧课设仓库保留作参考，不在原地硬修。

## 迁移顺序

### 阶段 1：建立新主仓库

- 从最新比赛代码新建独立仓库或独立工作副本。
- 保留比赛代码原有任务框架、通信框架、状态监控和日志链路。
- 旧课设仓库冻结，只读参考。

### 阶段 2：接入课设核心功能

- 搬入底盘控制逻辑。
- 搬入巡线解析与巡线控制入口。
- 固定 4 个 2006 电机的初始化、ID 和 CAN 收发路径。
- 保留模式切换，但只收敛到课设需要的模式。

### 阶段 3：保持最小调试能力

- 保留 `log_task` 和 `data_log`。
- 先只打印模式、巡线值、底盘输出、CAN 收发计数。
- 不要一开始接入过多曲线和大批量调试输出。

### 阶段 4：后续再接机械臂

- 机械臂单独成模块。
- 优先保证底盘和巡线闭环，再把机械臂接入任务框架。

## 当前已知风险

1. 底盘任务里局部变量作用域写法不规范，可能直接导致编译或逻辑问题。
2. 巡线输入链路存在残留变量，不能直接认为已经接好。
3. CAN ID 和滤波表需要和 4 个 2006 电机固定对齐。
4. 日志串口不要和主控制链路互相抢资源。
5. 任务注册如果同时保留多个旧入口，后续会难排查。

## 建议优先修改的文件

- `Core/Src/freertos.c`
- `Application/chassis_task.c`
- `Application/mode_switch_task.c`
- `Application/irtraking_task.c`
- `Comm/can_comm.c`
- `Comm/usart_comm.c`
- `Application/log_task.c`
- `Math/data_log.c`

## 近期执行清单

1. 先确认新主仓库可完整编译。
2. 把底盘和 4 个 2006 电机链路接通。
3. 把巡线数据接到底盘输入。
4. 保留日志但只开最小输出。
5. 最后再接机械臂。
