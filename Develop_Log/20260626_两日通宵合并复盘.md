## 二、CAN 总线（最长的弯路）

### 2.1 物理接线变更（多次）

| 时间 | 变更 | 原因 |
|------|------|------|
| 初始 | CAN1=IMU, CAN2=4×2006+arm_yaw | 旧架构 |
| 合并 | CAN1=4×2006, CAN2=arm_yaw(0x208) | 复制D:\已验证方案 |
| 重分配 | CAN1=IMU+4×2006, CAN2=仅arm_yaw | 用户物理改线，CAN3 接线有问题 |
| 最终 | CAN1=IMU+4×2006+arm_yaw(0x208), CAN2=空闲 | arm_yaw 从 CAN2 移到 CAN1 |

### 2.2 CAN ID 冲突（多轮排查）

1. **`uint8_t` 截断 0x201→0x01**: DJI CAN ID 11位，`uint8_t` 最大 255。`chassis_2006[3].can_id=0x01` → 全部路由到 idx3。修：改 `uint32_t`。**2026-06-24 合并时发现**
2. **shootTask 的 0x201~0x203 冲突**: `fric_motor[0/1]`+`trigger_motor` 的 CAN ID 跟底盘 4 个电机完全重叠。修：注释掉 `osThreadDef(shootTask)`。**2026-06-24 晚发现**
3. **ID 拨码错配(1↔2)**: 互换两个后电调后拨码没改回来，左后实为 ID1（代码认为 ID2）、右后实为 ID2（代码认为 ID1）。2026-06-24 深夜物理修正

### 2.3 硬件故障排查（占通宵一半时间）

| 症状 | 排查路线 | 最终根因 |
|------|---------|---------|
| 右前轮"从不转" | 换电调→换轮子→左前/右前互换→三相线→霍尔 | **`MaxOutput=500` 限幅太小**，放大到 8000 后正常 |
| 左后轮停不下来 | 0x202 CAN id冲突→电调互换→拨码检查 | **电调刹车电路损坏**（已换新电调） |
| 右后电调偶发重启 | 供电检查→BTB端子→连接器 | **电调已彻底损坏**（灯不亮，已换新） |
| 左后 CAN 反馈冻结 | DMA→队列→id冲突→物理检查 | **拨码错配**(ID1而非ID2)，物理修正后恢复 |
| CAN/SBUS 同时归零 | GDB→复位→BTB端子→CMSIS-DAP | **GDB attach 触发板子复位**(后放弃GDB，改用串口日志) |

### 2.4 关键教训

- "开环能转/闭环不动" → 优先查 PID `MaxOutput`，不要先怀疑硬件
- CAN ID 拨码 LED 闪烁次数 **不可信**(C610 曾有闪4下实际在0x201通信)
- GDB 单点读取在本环境下每次 attach 大概率触发复位，放弃改用串口日志

## 三、UART 分配历程（三轮大改）

### 3.1 初始分配

| USART | 用途 | 波特率 |
|-------|------|--------|
| USART1 | SBUS 遥控 | 100000 8E2 |
| USART2 | 8IR 巡线 | 115200 |
| USART6 | 调试(VOFA+dbg_print) | 921600 |
| USART10 | 视觉 | 115200 |

### 3.2 第一次轮换

用户要求：8IR 改到 U10，视觉改到 U6，调试改到 U2。

原因：8IR 模块物理接线只能接 U10，视觉模块只能接 U6，调试口跟着开发习惯走 U2。

### 3.3 第二次轮换（GPIO方案后）

8IR 放弃 UART 改用纯 GPIO→**U2 引脚变成 GPIO**→`MX_USART2_UART_Init()` 被注释→`huart2` 是野指针→`dbg_print(&huart2,...)` 触发 **HardFault**。

最终：**debug + VOFA 共用 U6**（互斥宏，不同时开），8IR 纯 GPIO 读 6 个引脚。

## 四、HardFault 排查（最有价值的部分）

### 4.1 第一次 HardFault：dbg_print 写未初始化 huart2

**时序**：8IR-GPIO 方案注释掉 `MX_USART2_UART_Init` → `chassis_task` 打印 `dbg_print`（目标 `DBG_HUART=huart2`）→ 访问野指针 → BusFault → HardFault。

**修复**：`DBG_HUART` 改回 `huart6`，同时 debug/VOFA 互斥检查恢复。

### 4.2 第二次 HardFault：USART6 RX DMA 从未配置

**修复后仍然硬** → GDB 硬件取证：`BFAR=0x60C11005`，PC=0800dc96 落入 `USER_UART_IDLECallback`。

**根因**：`huart6.hdmarx` 是野指针——CubeMX 只配了 `hdma_usart6_tx` 从未配 `hdma_usart6_rx`，但 `USER_UART_Init()` 对 `&huart6` 调用了 `HAL_UART_Receive_DMA`。

**修复**：注释掉 USART6 IDLE 中断使能 + RX DMA 启动，只留 TX（VOFA 发送路径）。**后续如果再要开视觉接收，必须补 CubeMX 的 RX DMA 配置。**

### 4.3 追加验证：悬空 RX 引脚噪声会饿死任务调度

视觉模块没接线时，USART6 RX 悬空噪声持续触发 IDLE 中断 → 任务调度被饿死。即使改成 IT 模式也一样。

**结论**：只有视觉模块物理连接 + CubeMX 配好 RX DMA 才开启 USART6 RX。

## 五、8IR 巡线模块（协议→GPIO 转型）

### 5.1 原方案

UART ASCII 协议：`$0,0,1#` 使能 → 模块回 `$D,x1:0,...#`(数字) + `$A,x1:4096,...#`(模拟)。

### 5.2 失败过程

1. UART 使能后 `digital` 全 0 → 怀疑校准问题 → 用户长按 KEY1 完成校准 → 数字仍全 0
2. 改用数字+模拟全开 `$0,1,1#` → 模拟量瞬间出数据，然后永远不变
3. 怀疑一发一收模式 → 每周期补发使能 → 来不及验证就被叫停

### 5.3 最终方案：纯 GPIO

放弃 UART，直接 HAL_GPIO_ReadPin 读 6 个引脚（X2~X7，对应 PE3/PE2/PB11/PB10/PA3/PA2）。

### 5.4 极性验证

- 全白 = `digital=111111` → `position=12`（原 `compute_position()` 把白判为"有东西"：是反的）
- 全黑 = `digital=000000` → `position=0`

**修复**：`if(digital[i])` → `if(!digital[i])`，使黑线压到时正确判为 1。

### 5.5 位置权重

从老代码 `irtraking_task.c` 搬运等距对称权重 `{-2.5,-1.5,-0.5,0.5,1.5,2.5}`，加权平均 + 归一化 ±100。6 个有效传感器（首尾 0 占位）。

## 六、PWM 舵机（两个关键 bug）

### 6.1 Bug ①：PA0/PA1/PA6 被配成 ANALOG 模式

**现象**：肩/肘/夹爪完全无反应，有供电但舵机自己回零。

**根因**：`gpio.c` 的 CubeMX 模板把这 3 个引脚配成了 `GPIO_MODE_ANALOG`。定时器 CCR 寄存器值正确变化，但物理引脚没接 TIM 输出通路。

**修复**：`PA0/PA1→GPIO_MODE_AF_PP + GPIO_AF1_TIM2`，`PA6→GPIO_AF2_TIM3`。LA 确认改后有波形。

### 6.2 Bug ②：Prescaler 83 按 84MHz 而非实际 275MHz 算

**现象**：LA 测出周期 6.1ms（应为 20ms），脉宽 ~150us 固定不变。

**根因**：H743 的 TIM2/TIM3 输入时钟 = 275MHz（APB1 DIV2→PCLK1=137.5MHz，H7 定时器自动×2）。代码按 F4 的 84MHz 算。

**修复**：`Prescaler=83→274`（275MHz/275=1MHz，周期 20ms 准确）。LA 验证通过。

### 6.3 三关节机械限位

以公式 `pulse=1500+angle/90*1000` 标定：

| 关节 | 方向1(角度) | 方向2(角度) |
|------|-------------|-------------|
| 肩 | 最抬(-15°) | 最放(38°) |
| 肘 | 最放(-5°) | 最抬(51°) |
| 夹爪 | 闭(-7°) | 张(-49°) |

### 6.4 ⚠️ 两套映射体系不统一

- **标定实测公式**：`pulse=1500+angle/90*1000`（已验证可工作）
- **prot_servo.c 正式映射**：`[angle_min,angle_max]→[500,2500]`（未验证）
- 两套给出不同 pulse 值，待统一

## 九、你踩过的最大弯路（教训汇总）

### 弯路排名

1. **右前轮"不动"排查（>3小时）**: 换轮子→换电调→互换测试→改拨码→查接线→怀疑三相线→最终 **PID MaxOutput=500 太小**。同一症状在不同时间点用不同的"原因"解释过(机械卡死/电调故障/接线松动/霍尔信号异常)，真正根因是最简单的参数配置问题。
2. **左后 ID 拨码错配（~1小时）**: 两个后电调互换后拨码没改回来，导致 idx1 反馈冻结，怀疑过 CAN id 冲突、shootTask 残留、电调硬件故障。
3. **SBUS 全部为 0（~2小时）**: 从接线怀疑到 BTB 端子→波特率→DMA 配置→最终 `DMA_DBUS_LEN=18` 不够 SBUS 帧长 25。
4. **HardFault 两次（~2小时）**: 第一轮 uart2 野指针，第二轮 USART6 hdmarx 野指针——**其实是同一个 bug 模式**(HAL 函数操作的 UART 外设/指针未初始化)，只是出现在两个不同 UART。
5. **PWM 两个 bug 同时存在（~1.5h）**: ANALOG 模式 + Prescaler 错误，使肩关节被误诊为"舵机没力"、"标定模式没起作用"。

### 黄金排查原则

- **"开环能转、闭环不动" → 先查 PID 限幅**，不查硬件
- **GDB 复位污染 → 放弃 GDB，改用串口日志**
- **Keil 增量编译不识别外部编辑改的文件 → 确认日志有 `compiling xxx.c...`，没有就用 `-r`**
- **两个改动之间的交叉影响 → 每次改完后 grep 确认所有引用点同步**
- **重试 OpenOCD 烧录一般 1~2 次成功，"failed erasing sectors" 不算真成功，必须确认 `wrote xxx bytes`**
