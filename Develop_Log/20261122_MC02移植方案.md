# 2026-11-22 主控移植方案：taurus → 达妙 MC02

> **架构修正**：达妙 MC02 是新主控板（单板架构），不是外挂 IMU 板。整车上只有这一块主控，固件全量移植。
> 基座：官方 `CtrBoard-H7_ALL` Keil 工程（opensource_ref/dm-mc02/例程/）——自带 BMI088 驱动+温控 PID、MahonyAHRS、imu_task（yaw/pitch/roll 直出）、CAN bsp、VOFA。

## 二、移植清单（taurus 业务 → MC02 ALL 工程）

### 第一批：基座就绪（今晚）
1. ✅ 官方 ALL 工程编译验证（后台进行中）
2. BMI088+MahonyAHRS+温控：官方 imu_task **原样保留**，补 yaw 输出到 VOFA——明天烧录即得 yaw 曲线
3. 引脚映射表（本文档）——现场核对实物排针后锁定

### 第二批：底盘链路（明天实验后实施）
4. `bsp_can` 适配：官方 can_bsp（FDCAN 兼容经典帧 1Mbps）替换 taurus 的 bsp_can；`prot_rm_motor` 业务不动（dji_motor 收发结构平移）
5. `chassis_task` + `chassis_can_send`：CAN1 单总线收敛，过滤器表同步
6. SBUS：`prot_sbus` 挂 USART1（PB7/PA9），100000 8E2 倒装协议不变

### 第三批：巡线+机械臂（依赖明天实验结果）
7. 巡线：`prot_8irtraking` v2（UART 流式模拟量 + GPIO 双模式）挂 UART10 或 GPIO；line_follower 模块（模拟量质心+置信度+yaw 航向保持）——yaw 本板直读，**原"串口传 yaw"环节删除**
8. 机械臂：PWM 路径用官方 8×舵机排针（bsp_pwm 重映射 TIM 通道）；串口路径 prot_xb_servo 的 UART4 引脚按 MC02 重映射
9. 避障：接近传感器 IO（排针空闲脚）

### 暂不移植
- shoot/gimbal/ui/fric/trigger 死代码（v2 直接不搬）
- 视觉 UART（模块未到货）
- USB/LCD/OV5640/WS2812/W25Q64（用不上）

## 三、明天现场流程（更新版）

1. **舵机验明正身**（servo_probe.py，CH343 直连舵机——与板无关，先行确认 PWM/串口路径）

## 五、巡线算法来源（子代理调研定稿，详见 20261121_巡线避障开源与舵机接口调研.md）

**首推参照：helu33/25-aiming-cart**（已克隆到 opensource_ref/）——2025 电赛 E 题，100cm 方形黑线环线+4 个 90° 弯按弯计圈，**同款 STM32H723+达妙 MC02**，场景 1:1：
- `chassis_mission.c` 状态机全套：**line_error 判定=压线灯≤3 个且空间连续**（直接消灭"边缘灯闪烁误触发"）、弯道 3 帧确认、`sqrt(v²+2·a·s)` 刹车曲线进弯、**陀螺仪角速度闭环转 90°**（转完 REACQUIRE 三条件回线）、触发点间距自学习计圈、丢线按上次误差符号 search_w 搜索+0.2s FAULT 兜底
- BMI088+Mahony 全套（恒温加热+14s 零偏校准）可直接抄，与官方 imu_task 同构

**次推**：5ee511/MSPM0G3507-Car——八路灰度加权差比和（权重 6/4.2/1.8/0）+PD(kp20/kd10)+直角弯状态机，2026-07 实车验证。

**避障**：无现成完整开源；方案=helu33 骨架改造 APPROACH/DODGE_OUT/DODGE_SIDE/DODGE_IN/REACQUIRE 状态链（地图已知化）。

**舵机双接口定论**：两接口=同一半双工 UART 总线的级联并联（CAN 进/出式），非 PWM 输入——SP-30S 商品实拍全篇"串行总线/角度回读"零 PWM 字样（A 级），京东同品牌 PWM/总线为独立 SKU（B 级）。明天实验仅作最终确认。

**BMI088 滤波选型**：Mahony（官方 imu_task 已带，helu33 同款）足够；VQF 是升级选项（算力开销大）。底盘实际只需要 gz 积分+航向修正。

## 六、权威引脚表（来源：官方 CtrBoard-H7_ALL.ioc 文本解析 + H7_BSP 社区开源交叉核对，推翻此前视觉读图版）

> 纪律：引脚以 .ioc 为准；管脚图 PDF 仅当线索；本表已三方印证（官方 .ioc × H7_BSP fdcan.c 完全一致）。

| 外设 | 引脚（ioc 权威） | 分配给 taurus |
|---|---|---|
| FDCAN1 | RX PD0 / TX PD1 | **底盘 4×2006 + yaw 6020（1Mbps 经典帧）** |
| FDCAN2 | RX PB5 / TX PB6 | 备用 |
| FDCAN3 | RX PD12 / TX PD13 | 备用 |
| USART1 | TX PA9 / RX PA10 | **SBUS 遥控**（100000 8E2 倒装） |
| UART7 | TX PE8 / RX PE7 | **prot_xb_servo 串口舵机**（115200，若实验确认串口舵机） |
| USART10 | TX PE3 / RX PE2 | **8IR 巡线模块串口**（115200，模拟量流式） |
| USART2 | TX PD5 / RX PD6 / DE PD4 | RS485_1（备用） |
| USART3 | TX PD8 / RX PD9 / DE PB14 | RS485_2（备用） |
| SPI2 (BMI088) | SCK PB13 / MOSI PC1 / MISO PC2_C | 板载 IMU（官方驱动） |
| TIM PWM | PA0=TIM2_CH1、PA2=TIM2_CH3、PB1=TIM3_CH4、PE13=TIM1_CH3、PE9=TIM1_CH1、PB15=TIM12_CH2 | PWM 舵机候选通道（对照 CtrBoard-H7_TIM 例程选 3 个） |
| OCTOSPI2 (W25Q64) | CLK PB2 / IO0 PD11 / IO1 PB0 / IO2 PA3 / IO3 PA1 / NCS PE11 | 板载 flash——**示教动作组存储候选** |
| GPIO_OUT | PC13/PC14（OUT_EN 电源使能组）、PB10/PB11/PB12/PC0/PC5/PD10/PE15 | 供电使能 + 避障传感器的可用 IO 从中选 |
| GPIO_IN | PA15(User Key)、PE10/PE12(外部中断) | 按键 + 接近传感器中断候选 |
| ADC | PA5(INP19)、PC4(INP4) | 电池电压采样候选 |
| RCC | AXI 240MHz / APB1=APB2=120MHz | 与 taurus 旧工程时钟不同（TIM 时基重算！） |

**注意**：PA3 是 OCTOSPI IO2（不是舵机口）；CAN2 是 PB5/PB6（不是 PB12/13）；BMI088 SPI2 SCK=PB13——全部以本表为准。

## 七、串口健康打印体系（设计定稿，移植即实现）

用户开发习惯=纯串口打印（无调试器）。设计如下，随基座移植落地：

### 7.1 启动横幅（上电一次）
```
=== TAURUS v2.0 @ DM-MC02  build 2026-11-22 __TIME__ ===
[OK] HAL Init / [OK] CAN1 1Mbps / [FAIL] SBUS RX ...   ← 每个外设 init 逐项打 OK/FAIL
[OK] BMI088 init (temp 26C) / [OK] FreeRTOS start
```

### 7.2 1Hz 健康包（debug UART，DEBUG_TEXT_ENABLE 控制）
```
[SYS] cpu=23% min=1% max=61%  heap=12.4K/64K  up=00:12:34
[TASK] chassis=982/s mode=LINE arm=PROT lineconf=87%
[CAN1] tx=1180/s rx=1180/s lost=0  err=0   ← send/receive_cnt 差值即丢包
[U7]   servo tx=6 rx=5 online=1,1,1        ← 舵机总线
[U10]  8IR frames=100/s conf=0.87          ← 巡线流式
[SBUS] frames=140/s ch1..4=[1024,1024,...] online=1  ← 丢失时 online=0+计数
[IMU]  yaw=42.3deg drift=0.8/min temp=40C  ← BMI088 恒温确认
```

### 7.3 实现要点
- `health_task`（osPriorityBelowNormal，1Hz）：读 FreeRTOS runtime stats（.ioc 已配 SYS=tim23，开 `configGENERATE_RUNTIME_STATS=1` 即得 CPU%）、各任务 alive 计数表（任务循环内自增，健康任务对比 idle 统计）、CAN/UART 计数差值
- 通道复用现有 debug/VOFA 互斥机制（DEBUG_TEXT_ENABLE/DEBUG_VOFA_ENABLE 不能同开，沿用）
- 机械臂/底盘/巡线状态从模块状态机直接取（v2 的 Module 层暴露只读状态接口，health_task 只消费）
