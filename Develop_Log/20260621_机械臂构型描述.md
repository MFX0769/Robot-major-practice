# 机械臂构型描述

## 观察对象

来源：单张机械臂结构图。

这是一套车载采摘机械臂，整体由底座安装平台、上臂机构、下臂机构和末端夹持机构组成。结构上更接近“底座回转 + 平面两连杆抬升 + 末端夹爪”的轻量采摘机构，而不是自由度很多的通用六轴机械臂。

## 构型描述

### 1. 总体形式

该机械臂安装在移动底盘上，底部通过支架固定于车体。臂体主体沿一个主工作平面展开，主要完成“抬升、伸出、夹取、收回”这一类动作。

从结构关系上看，它具备以下特征：

- 具备一个底座回转关节，用于调整机械臂在平面内的指向。
- 上臂与下臂构成主要工作链路，完成末端空间位置的到达。
- 机构中存在明显的平行四边形/连杆约束特征，说明末端姿态并非完全自由，而是带有一定的姿态保持能力。
- 末端是夹爪式执行器，更偏向抓取和夹持，而不是高自由度的手爪操作。

### 2. 关节与连杆关系

从图上可将其概括为：

- **J0**：底座回转关节，负责方位角调整。
- **J1**：肩关节，负责上臂抬升。
- **J2**：肘关节，负责下臂伸缩。
- **J3**：末端夹持/腕部关节或夹爪执行机构，负责末端动作。

由于图中存在连杆平行约束，J1 与 J2 之间并不是单纯的“完全裸露串联两转轴”视觉形态，而是通过连杆机构形成稳定支撑。这个结构的直接效果是：

- 能提升末端姿态稳定性；
- 能降低末端姿态乱翻的风险；
- 也会让运动学建模时需要把连杆偏置和安装角度考虑进去。

### 3. 末端执行器

末端夹具为环状/弧形夹持机构，形态上更接近“包覆式夹取”而不是点式抓取。它适合对目标进行包裹、夹持或托举，说明系统的任务目标是采摘和搬运，而不是精密装配。

## 从建模角度的含义

这套结构非常适合做简化 DH 建模，原因是：

1. 主体自由度较少。
2. 主要运动集中在一个工作平面内。
3. 底座 yaw 与平面两连杆可以分层处理。
4. 末端执行器的姿态要求不高，可以把夹爪单独抽象掉。

推荐的建模思路是：

- 先建立底座回转坐标系；
- 再建立肩关节、肘关节的平面串联模型；
- 将夹爪视为末端工具坐标系的偏置；
- 用 DH 参数描述连杆长度、轴向和零位偏置；
- 在逆解中优先求末端位置，再决定夹爪开合。

## 代码实现建议

### 任务层

机械臂控制应单独放在 `arm_task` 中，任务层只做流程编排：

- 接收视觉输入或上层目标；
- 调用逆运动学；
- 调用关节限位；
- 调用平滑/插值；
- 下发 PWM 舵机目标值；
- 控制供电使能/失能。

### 算法层

建议单独放一个运动学模块，例如 `arm_ik.c/.h`，内容包括：

- 末端目标到关节角的逆解；
- 关节角限位；
- 接近目标时的减速或步进平滑；
- 末端目标的简单修正；
- 必要时的零位偏置补偿。

### 执行层

PWM 舵机控制建议单独封装，不直接散落在任务层里：

- 角度到脉宽映射；
- 脉宽范围限幅；
- 舵机方向反转；
- 供电使能/失能；
- 异常时断电保护。

## 由图可做的工程级判断

### 可以较确定的部分

- 机械臂是串联式主链路。
- 主要工作自由度集中在底座和两级臂段。
- 末端执行器是夹爪。
- 适合用平面两连杆加底座 yaw 的方式建模。

### 不能仅凭图片定死的部分

- 每个关节的精确角度限位；
- 每个转轴的准确安装偏置；
- 连杆精确长度；
- 是否存在机械止挡；
- 是否允许完全伸直到奇异位形附近。

这几项需要实物测量或者 CAD 尺寸表确认，不能只凭一张图下结论。

## 奇异位形与限位说明

这类结构通常会在肩关节和肘关节接近共线时出现奇异性增强，表现为：

- 末端微小位移需要关节较大变化；
- 逆解对误差更敏感；
- 动作容易显得突兀。

因此工程上应当在代码中加入：

- 关节角限位；
- 目标点工作区限幅；
- 接近边界时降速；
- 输出前脉宽兜底限幅；
- 必要时的断电保护。

## 无反馈标定建议

由于舵机没有额外位置反馈，关节零点和角度映射需要通过开环方式人工标定。可采用调试模式逐步输出不同 PWM 脉宽，结合肉眼观察和机械止挡确认每个关节的可用范围、方向和中位偏置。

建议流程：

1. 先固定单个关节，断开其他关节的动作权限。
2. 在 debug 模式下以小步长扫描 PWM 脉宽，记录每个脉宽对应的实际角度和接近机械极限的位置。
3. 找到中位附近的稳定点，作为该关节的 `zero_offset`。
4. 找到正反向的安全边界，作为 `pulse_min` 和 `pulse_max`。
5. 重复检查关节方向是否与软件定义一致，不一致则在软件层反向。
6. 所有关节完成后，再做整臂联动验证，检查是否会在某些组合姿态下互相干涉或接近奇异位形。

这个方法的核心是把“位置标定”拆成“单关节开环标定 + 整臂组合验证”，先得到可用参数，再谈更高层的运动学和动作序列。

### Keil Debug 标定方式

开发阶段可以直接利用 Keil 的 debug 能力修改全局变量，不必额外写完整的标定 UI。

建议做法：

- 将每个舵机的 `pulse_min`、`pulse_max`、`pulse_zero`、`direction`、`current_pulse` 暴露为全局结构体成员；
- 在 Keil Watch 窗口直接修改这些变量；
- 单步观察关节运动和机械止挡位置；
- 用变量写回的方式完成零点和限位标定；
- 运行态只保留最小舵机接口，不把标定逻辑带进正式控制链路。

这种方式适合当前开发阶段，优点是实现成本低、反馈快、便于逐关节排查。

## 简短结论

这是一套结构清晰的车载采摘机械臂，主链路可以抽象为：

**底座 yaw + 肩关节 + 肘关节 + 末端夹爪**

建模上适合使用 DH 参数法，控制上适合采用“逆解 + 限位 + 平滑 + PWM 舵机输出”的轻量闭环方案。
