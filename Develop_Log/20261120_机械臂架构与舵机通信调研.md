## 0. 一页结论（TL;DR）

1. **舵机真相**：随硬件资料包（`Source/servo/`）来自杭州**星呗**科技（xbrobot.taobao.com，任务书里写的"星晖"是误记）。资料包含**两条产品线**：串行总线舵机（SP-15/20/30S/D，单线 UART 文本协议）和 PWM 舵机（另一份手册）。本地日志把车上舵机记为 **"PD30S"**，经查证它不是标准型号名（联网只查到 CUI Devices 的 PD-30S 电源插座，无关），本地《电源拓扑与舵机供电分析》自己把它映射为 **SP-30S（单轴，30kg·cm 总线舵机）** [A/C]。但《电源拓扑》里"PWM(兼容)/串行总线双模式"这一行**没有任何一手证据**（串口手册和淘宝商品页都只写串口）[C]。
2. **2026-06-25 的遗留疑点成立**：那晚只修好了 PWM 波形（逻辑分析仪验证），"舵机实际动没动"从未验证。也就是说现在车上可能根本没验证过舵机能被 PWM 驱动。
3. **建议**：先做一个 5 分钟决定性实验（USB-TTL 115200 发 `#000PVER!`，有 `#...G!` 回复→是总线舵机）。若是总线舵机，**切串口方案**：位置回读（闭环/示教/堵转保护）、内置 T 参数速度规划、`PULK` 释力拖动示教、掉电保存标定，收益全面大于 PWM。PWM 方案不删代码（bsp_pwm/prot_servo 保留作保底），但新代码不再走它。
4. **最值得抄的开源**：① `Chenxi-Li24/OmniX_Engineer`（RMUL2026 上海站冠军，H723 + 串行舵机驱动层/开机自检/标定表/诊断，2026 赛季同代架构）；② `SJTU-RoboMaster-Team/Matrix_and_Robotics_on_STM32`（186★，机械臂机器人学库，IK 层参考）；示教回放范式参考 `chronhai/lite_Recording_Board`。
5. **架构要点**：三层不变（Bsp → Protocol → Application），`prot_servo` 平行新增 `prot_xb_servo`（串口总线驱动，PWM 的 prot_servo 不删），arm_task 状态机扩成 7 态（PROTECT/IDLE/MANUAL/DEMO/TEACH/PLAY/AUTO），`arm_busy` 作为与底盘的联锁契约保持不变。

### 1.2 KSP 串行总线舵机协议全表 [A]

来自 `串行总线舵机指令表.pdf` + `串行总线舵机使用手册.pdf`（两份 PDF 一致）：

**物理层**
- 单线串行总线（**半双工单信号线**，TX/RX 同线）。3 根线：V+ / GND / Signal，接口 5264-3P，每个舵机 2 个同功能接口便于级联。
- 供电 5~8.4V（正负极兼做电源）；**信号电平未明说**（舵机内控芯片；3.3V MCU 的 TX 直接驱动是常规用法，H7 引脚 FT 5V 耐受，RX 侧建议加几百欧串阻）[A/C]。
- 波特率默认 **115200**（8N1，无校验无流控），可改 9600/19200/38400/57600/115200/128000/256000/1000000（`#000PBDn!`，n=1~8）。
- 级联最多 255 个，**手册建议单根线 ≤6 个**。所有字符大写，以字符串发送接收。
- **读位置需要单总线模式**：只控制时 MCU 的 TXD 接舵机信号线即可；要回读角度，必须把 UART 配成单线半双工（STM32 原生支持 HDSEL），或买厂商 USB/TTL 调试板转双线。
- 手册硬件注意事项：舵机电源线禁用杜邦线（堵转 2.3~3A）；舵机与 MCU 非同电源时必须共地；舵机不能只用电脑 USB 供电。

### 1.4 决定性实验（5 分钟，切方案前必做）[C]

1. 舵机接 USB-TTL（V/GND/Signal，Signal 接 TXD；要回读则把 TXD RXD 短接成单线）。
2. 串口助手 115200-8N1，发 `#000PVER!`：
   - 回 `#000PZServo Vx.xxG!` → **是总线舵机**，走串口方案；
   - 无回复且发 `#255PID!` 也无回复 → 再用 50Hz/1500us PWM 试转：动了 → 是 PWM 线产品，走 PWM 方案；
   - 都没反应 → 检查供电/共地/ID 后重试（也可能是马达模式，但概率低）。
3. 顺手记录：上电是否自动回 1500（CSM 开机模式）、当前 ID（`#000PID!`）。

### 1.5 结论：PWM 还是串口？

**若决定性实验确认是 SP 系列总线舵机 → 切串口。**理由（对照 PWM 现状）：

| 能力 | PWM 现状 | 串口总线 |
|------|----------|----------|
| 位置反馈 | 无（开环，只能逻辑分析仪+人眼标定） | `#xxxPRAD!` 回读角度；`PRTV` 温度/电压 |
| 速度规划 | 自己写插值 | 指令自带 T 参数，舵机内部完成运动 |
| 示教 | 不可行（无反馈） | `PULK` 释力→手扳→`PRAD` 采样→存关键帧 |
| 堵转/过热保护 | 无 | 手册标称堵转保护、过温保护（配合 PRTV 监控） |
| 标定持久化 | 上电重标 | `PSCK/PSMI/PSMX/PCSD` 掉电保存 |
| 布线 | 3 根独立信号线（PA0/PA1/PA6） | 1 根信号线级联 3 个舵机 |

**PWM 方案处置**：`bsp_pwm.c` + `prot_servo.c`（含 2026-06-25 实测限位标定数据：肩 -15~38°、肘 -5~51°、夹爪 -49~-7°，还有"两套 angle→pulse 映射不一致"的遗留问题）**保留不删**，作为保底与对照；2026-06-25 标定的机械限位角度数据与新方案通用（角度限位是机械属性，与驱动方式无关）[A]。

**切串口的硬件接口清单（H723VGTx）**：

| 资源 | 状态 | 依据 |
|------|------|------|
| USART1 (PA9/PA10) | SBUS 遥控接收占用 | [A] `Comm/usart_comm.c` IDLE 回调 `dma_sbus_buf` |
| UART9 (PD14/15) | new_rc 遥控占用 | [A] 同上 `dma_new_rc_buf` |
| USART6 (PC6/PC7) | 视觉 + 调试打印 921600 占用 | [A] `prot_vision.c`/`config.h` |
| USART2 (PA2/3)、USART3 (PB10/11)、USART10 (PE2/3) | 引脚已被 8 路灰度传感器改配 GPIO 数字输入 | [A] `main.c` 注释 + `prot_8irtraking.c` 逐脚 ReadPin |
| **UART4：TX=PC10 / RX=PC11（AF8），或 TX=PB9 / RX=PB8** | **空闲**（ioc 未配置这三组脚） | [A] ST DS13313 Rev5 Table 8 + 本地 ioc 引脚清单 |
| UART7：TX=PE8 / RX=PE7 | 空闲备选 | [A] 同上 |

推荐 **UART4，PC10 作单线半双工总线**（STM32 USART 开 `HDSEL` 后用 TX 脚收发同一根线，正好匹配舵机单线制；PC10 只接第一个舵机的信号口，舵机之间用自身双 5264 接口级联）。需现场确认达妙 MC02 板排针是否引出 PC10/PC11（或 PB8/PB9）[C 待查]。电气：MCU TX→舵机 Signal 直接连，串 330Ω~1kΩ 保险电阻；共地；舵机供电走现有外置降压+PA7 NMOS 使能链路不变。

### 1.6 串口舵机协议驱动接口清单（prot_xb_servo 待写）

```c
/* ---- Protocol/prot_xb_servo.h（拟） —— 星呗/SP 系列单线总线舵机驱动 ----
 * 物理层：UART4 PC10, 115200-8N1, USART_HDSEL(单线半双工), TX 后等响应
 * 线程模型：控制任务调用；回读请求-应答用互斥包住（半双工单线，一次只发一条）
 */

typedef enum { XB_SHOULDER = 0, XB_ELBOW, XB_GRIPPER, XB_NUM } xb_servo_id_e;   /* ID 在板级配置里映射 */

/* 基础 */
void    xb_servo_init(void);                       /* UART4 HDSEL + 总线自检(逐个 PVER/PID) */
bool    xb_servo_online(uint8_t id);               /* 有无应答（周期 PING 或读失败计数） */

/* 控制 */
void    xb_servo_move(uint8_t id, uint16_t pulse, uint16_t time_ms);  /* #id P pulse T time! */
void    xb_servo_move_group(const uint8_t *ids, const uint16_t *pulses, const uint16_t *times, uint8_t n); /* 多条拼接直发 */
void    xb_servo_torque_off(uint8_t id, bool big); /* PULK / PULM 释力（示教） */
void    xb_servo_torque_on(uint8_t id);            /* PULR */

/* 回读（单线半双工，带超时与重试） */
int8_t  xb_servo_read_pos(uint8_t id, uint16_t *pulse);        /* PRAD → 解析 #idPxxxx! */
int8_t  xb_servo_read_tpv(uint8_t id, int8_t *temp_c, uint8_t *volt); /* PRTV → #idTxxVx! */

/* 配置（标定/安装时用，运行时不必频繁调用） */
int8_t  xb_servo_set_id(uint8_t old_id, uint8_t new_id);       /* PID */
int8_t  xb_servo_set_mode(uint8_t id, uint8_t mode);           /* PMOD1~8 */
int8_t  xb_servo_save_zero(uint8_t id);                        /* PSCK 中值校准（掉电保存） */

/* 角度域适配层（沿用 prot_servo 的标定思路，把 2026-06-25 实测角度限位搬过来） */
float   xb_pulse_to_deg(uint8_t joint, uint16_t pulse);        /* 500~2500 → 关节角（含零位/方向） */
uint16_t xb_deg_to_pulse(uint8_t joint, float deg);            /* 含 angle_min/max 限幅 */

/* 底层（bsp 侧） */
/*  bsp_usart4_singlewire_init(): HAL_UART_DeInit + huart4 + USART_CR1_HDSEL + 115200
 *  收发：HAL_UART_Transmit(TX 后) + HAL_UART_Receive(限时) 或 DMA+IDLE；
 *  注意半双工方向翻转期间丢弃回显字节（HDSEL 自环不回显，但舵机响应要清 ORE） */
```

实现要点（对照厂商例程与开源实践）：所有帧是 ASCII 文本，`snprintf` 组帧即可；每条控制指令 ~16 字节 @115200 ≈ 1.4ms，一个 3ms 控制周期发一条没问题；**读位置是请求-应答式**，务必串行化（同一时刻只允许一个未完成请求），超时 20~50ms 判离线并保持上次值 [A/C]。

### 2.3 IK 层与关节控制层怎么衔接（供对照本地 arm_ik.c / matlab_sim）

三个开源范式：

```
范式A 关节空间关键帧（RM 工程主流: OmniX / 华北理工 / PRIME / lite_Recording_Board）
  示教/手捏关键帧 → {关节角(raw), 运动时间} 序列存 flash → 回放逐帧下发
  → 不需要 IK；贴合 RM"动作重复性高、点位固定"的场景。OmniX 用三联标定表做 关节↔舵机↔raw 映射。

范式B 解析闭式 IK（本地 arm_ik.c / TaurusArm / SJTU ikine_analytic）
  末端 (x,y,z[,姿态]) → 几何闭式解 O(1) → 关节角
  → 前提：构型简化（平面两连杆+yaw）、限位/奇异位形显式处理。
  TaurusArm 补的两件事是本地缺的：分支选择（肘上/肘下解）、解连续性（相邻目标取最近解）。

范式C 数值迭代 IK（SJTU 库 ikine 牛顿法）
  任意构型通用，但 6 轴 3~20ms/次 + 需要初值和调参 → H723 可跑，但 4 轴场景收益为零。
```

**衔接层（三层都一样）**，本地实现落位建议：

```
视觉/遥控目标 (x,y,z)
   │
arm_ik.c 解析IK → arm_joint_t{yaw, shoulder, elbow, gripper}（度）   ← 补：分支选择+解连续性+可达性诊断
   │
arm_joint_limit() 限位（度域，用 2026-06-25 实测机械限位）
   │
arm_joint_smooth() 步进插值（每周期 step；串口方案下可改为"发T参数让舵机自己走"，插值只做起点-终点过渡）
   │
标定映射层  deg → pulse(500~2500) / deg → 6020 电压-角度        ← OmniX 的 servo_joint_calib_t 三联表样式
   │
├── 舵机执行器: prot_xb_servo（串口）或 prot_servo（PWM保底）
└── yaw 执行器: GM6020 CAN 电压模式（现有 arm_yaw_pid_calc + ECD 硬限位回拉）

夹爪(gripper)在 arm_ik 里只是末端工具偏置+开合量，建议单独工具层接口，不进位姿解算闭环——
与《20260621_机械臂构型描述.md》"把夹爪视为末端工具坐标系偏置"的结论一致。
```

## 三、任务 3：机械臂模块架构设计要点（重写 arm 模块的素材）

对照 Meta-Embedded-NG 三层（application/bsp/module + robot_def.h 集中契约，见 `Develop_Log/20261120_开源电控代码规范调研.md`）与本地 `Bsp/ → Protocol/ + Comm/ → Application/` 同构分层：

### 3.1 模块划分

| 层 | 现状 | 改动 |
|----|------|------|
| Bsp | `bsp_pwm.c`(TIM2/TIM3 PWM)、`bsp_usart.c`（通用 IDLE+DMA 收）、`bsp_gpio.c`(PA7 NMOS) | 新增 `bsp_uart4_singlewire()`（UART4 PC10，HDSEL 单线半双工，115200）；**bsp_pwm 保留**（保底不删） |
| Protocol（模块层） | `prot_servo.c/h`（PWM 映射+标定限位） | **平行新增** `prot_xb_servo.c/h`（1.6 节接口清单），PWM 版改名 `prot_servo_pwm` 或加命名空间前缀区分；角度限位标定数据（肩-15~38/肘-5~51/夹爪-49~-7）从 prot_servo 提取到公共头，两驱动共用 |
| Application | `arm_task.c`（PWM 测试态+固定姿态表演）、`arm_ik.c` | arm_task 按 3.3 状态机重写；arm_ik 补分支选择/解连续性 |
| 契约 | 散在 control_def.h / arm_task.h | 新建 `robot_def.h` 集中：arm_busy、arm_joint_t/arm_pos_t、arm 状态枚举、chassis↔arm 联锁常量（湖大铁律：应用层不出现片上外设代码；上交 MAP 段二次定义引脚/句柄） |

### 3.2 关节接口定义草案（C 结构体+函数签名）

```c
/* ---- Application/robot_def.h（拟） ---- */
typedef enum { ARM_JYAW = 0, ARM_JSHOULDER, ARM_JELBOW, ARM_JGRIPPER, ARM_JOINT_NUM } arm_joint_e;

typedef struct {
    float yaw;        /* 底座 6020, 度, 车体系 */
    float shoulder;   /* 肩, 度 */
    float elbow;      /* 肘, 度 */
    float gripper;    /* 夹爪开合, 度 */
} arm_joint_t;        /* 与现有 arm_ik.h 的 arm_joint_t 对齐 */

typedef enum {
    ARM_ST_PROTECT = 0,  /* 失控/保护: 舵机释力或回零, yaw 输出清零 */
    ARM_ST_IDLE,         /* 上电初始: 供电未开, 等待解锁 */
    ARM_ST_HOME,         /* 回零: 一次性动作, 完成后进 IDLE_READY */
    ARM_ST_MANUAL,       /* 手动: 遥控通道直控各关节 */
    ARM_ST_DEMO,         /* 演示: 关键帧序列时间戳驱动(现有表演态扩展) */
    ARM_ST_TEACH,        /* 示教: 舵机释力, 周期 PRAD 采样存帧 */
    ARM_ST_PLAY,         /* 复现: 逐帧下发示教序列 */
    ARM_ST_AUTO,         /* 自动: IK 目标控制(视觉/上位机) */
} arm_state_e;

/* ---- Application/arm_joint.h（拟, 关节层 = 标定映射 + 驱动选路） ---- */
typedef struct {
    uint8_t  xb_id;        /* 总线舵机 ID（串口方案） */
    uint8_t  pwm_ch;       /* PWM 通道（保底方案） */
    uint16_t pulse_min, pulse_zero, pulse_max;   /* 500~2500 */
    float    deg_min, deg_max;                   /* 2026-06-25 实测机械限位 */
    float    deg_per_pulse;                      /* 270°/2000 */
    int8_t   dir;          /* 方向 ±1 */
} arm_joint_cfg_t;

void   arm_joint_init(void);
void   arm_joint_set_target(arm_joint_e j, float deg, uint16_t time_ms);  /* 单关节 */
void   arm_joint_set_all(const arm_joint_t *t, uint16_t time_ms);         /* 整臂同步 */
void   arm_joint_update(void);                        /* 每控制周期调用: 限幅+下发+状态更新 */
float  arm_joint_get_angle(arm_joint_e j);            /* 串口方案=PRAD 回读; PWM 方案=指令值 */
bool   arm_joint_online(arm_joint_e j);               /* 串口=总线应答; PWM=常true */
void   arm_joint_relax(void);                         /* 全部释力(示教/保护) */
```

要点：**关节层把"驱动方式"藏在 arm_joint_cfg 的两条路径里**——上层（状态机/IK）永远只说"这个关节给我到 X 度，用 Y ms"，不关心下面是 UART 文本还是 PWM 脉宽（Meta-NG/湖大"应用层无外设代码"铁律的落地）。

### 3.3 模式状态机与迁移

```
PROTECT ──(遥控恢复)──> IDLE ──(SW触发)──> HOME ──(到位)──> IDLE_READY
   ▲                    │                                        │
   │失控/过温/IWDG      ├────> MANUAL(遥控通道直控)              ├──> DEMO(关键帧)
   │                    ├────> TEACH(释力+PRAD采样, SW确认存帧)   ├──> PLAY(回放)
   └────────────────────┴────> AUTO(视觉/上位机目标→IK)          └────┘
任何状态: 检测到 ctrl_mode==PROTECT / 关节离线 / PRTV 过温 → 强制跳 PROTECT
```

- **示教（TEACH）**：`xb_servo_torque_off(PULK)` → 人手扳臂 → 50~100Hz `PRAD` 回读 → 按角变化阈值去重存帧 `{joint_raw[], time_ms}` → flash（H723 内部 flash 或 W25Q64，范式同 lite_Recording_Board）。
- **复现（PLAY）**：逐帧 `xb_servo_move_group()`，帧间隔用**舵机 T 参数保证到位**（比 20260625 设想的"纯计时器推进"更可靠——T 是舵机内部闭环），大帧间再留 20~50% 余量；PRAD 校验到位后进下一帧。
- **保护（PROTECT）**：沿用现有双重保险（yaw PID target 跟随反馈+输出清零），加第三重：舵机 `PULM` 大阻力释力或回零（可配）；`arm_busy=0` 立即放行底盘。
- **DEMO**：保留现有 `didx` 关键帧表演（SWD 触发），关键帧表数据化到 flash/数组，不再散在 switch-case。

### 3.4 与 yaw 6020 / 底盘 arm_busy 的联锁整合

- **yaw 与三舵机的协同**：IK 输出的 `joint.yaw` → 6020 角度目标（先补 2026-06-25 遗留的"yaw 零位标定"：ECD 1018/3988 硬限位已有，中点未标）。肩/肘动作期间 yaw 保持锁定（target=fdb），避免臂平面外甩。
- **arm_busy 契约**（保持现有语义，写进 robot_def.h）：
  - 置位：HOME/DEMO/PLAY/AUTO 任一执行中、或任一关节 `|target-当前|>阈值`；
  - 清零：PROTECT、MANUAL、IDLE、动作序列结束；
  - 消费方：chassis_task 读 `arm_busy` 限速/锁平移（现有逻辑不动）；arm 侧**只写自己**，符合上交"尽量读取而非写入"。
- **供电链**：PA7 NMOS 保持"遥控 SW 上电使能"现有逻辑；串口方案下上电顺序建议：NMOS 开 → 200ms → 总线 PING 自检 → HOME（对照 OmniX 的 SERVO_BOOT_WAIT_ONLINE 带重试回零）。
